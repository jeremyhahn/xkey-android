# 343: tests for the phone's attested identity

## Objective

Cover the three trust anchors of a paired session with tests of their own:
the Device Attestation Key that signs the pairing attestation, the binding of
that attestation to the Noise channel (`sessionBinding()`), and the CA-issued
identity enterprise enrollment gives the phone (`DeviceIdentity`). Every bug a
test finds lands as a failing-test commit followed by its fix.

## Slices, in order

1. `SessionBindingsTest` (JVM, `app/src/test`): real Noise handshakes between
   `NoiseInitiatorSession` and `NoiseSession`.
   - the binding is null before and part-way through the handshake, on both ends;
   - once complete it carries the static keys in handshake roles and the
     prologue, and both ends compute the same binding (first pairing and a
     known-device reconnect);
   - `copyOf()` does not alias the original or the session.
2. `DeviceAttestationKeyLifecycleTest` (device, `app/src/androidTest`):
   - `chain()` creates the key once and is stable across calls;
   - `rotate()` yields a new leaf and fingerprint;
   - the leaf carries the attestation extension with the genesis challenge;
   - `sign()` verifies with the leaf key; `sign()` without a key throws;
   - a stored alias with an unusable chain is replaced, not returned;
   - the alias is deleted after each test.
3. `DeviceIdentityEnrollmentTest` (device):
   - enrollment request validation, pending vs active state;
   - `storeCredential` refusals leave the active identity untouched;
   - a successful store retires the previous generation and advances it;
   - no stale pending key after a failed store;
   - `isCredentialExpired` around notAfter, `credentialChain()` order;
   - `reset()` removes every key and preference.
4. Each bug found: a commit with only the failing test, then the fix in
   `DeviceAttestationKey.kt`, `DeviceIdentity.kt` or `SessionBindings.kt`.
   Found and fixed:
   - an initiator's `sessionBinding()` shared the session's key arrays;
   - `chain()` returned a stored lone self-signed key as the DAK chain;
   - `isCredentialExpired` called a credential expired at its notAfter.
   - `sign()` mints a key when none is stored (its contract), so "sign with
     no key" is covered as a key the Keystore refuses to sign with.

## Out of scope

- Changes to `KeystoreManager.kt` or `BiometricHelper.kt` (an open pull
  request changes them): a bug there is reported, not fixed here.
- Repeating the existing `DeviceAttestationKeyTest` and `DeviceIdentityTest`
  cases; new dependencies; running Gradle (no Android SDK in the lane).
