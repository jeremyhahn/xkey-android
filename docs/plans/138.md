# Plan: build and verify a signed release (#138)

## Objective

Nothing builds a release or checks its signature. Add `make release-check`:
it makes a throwaway keystore under `build/`, builds `assembleRelease` with
the four `XKEY_*` variables `app/build.gradle.kts` reads, runs
`apksigner verify --print-certs` on the APK, and fails unless the APK has
exactly one signer whose certificate SHA-256 digest is the throwaway one.

## Slices

1. This plan.
2. `scripts/release-check.sh` and the `release-check` Makefile target.
   - Keystore: PKCS12, RSA 2048, one-day validity, random password, in
     `build/release-check/` (ignored by `/build/*`), deleted on exit.
   - Refuses to run when `keystore.properties` exists at the repository
     root: the file wins over the environment, so the build would be signed
     with another key.
   - `RELEASE_CHECK_OMIT=<XKEY_* name>` builds without that variable, so
     the target fails: the script exits 1 ("release build refused") when
     Gradle exits nonzero with the guard's "Release signing is not
     configured." message, and 2 ("GUARD BROKEN") when Gradle succeeds
     (an unsigned APK) or fails for another reason.
   - apksigner comes from `$ANDROID_HOME` (or `$ANDROID_SDK_ROOT`)
     `/build-tools/$ANDROID_BUILD_TOOLS` (scripts/tool-pins.sh), or
     `APKSIGNER=`.
   - Tests: the target itself; run green once, and once with
     `RELEASE_CHECK_OMIT=XKEY_KEY_ALIAS` (exit 1, refused), and once with
     the guard removed locally (exit 2, GUARD BROKEN).
3. `docs/release-signing/architecture.md` names the target (Components,
   Tests).
