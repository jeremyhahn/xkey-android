# Plan #259: SPEC row co-signing

## Objective

Row `co-signing` of docs/SPEC.md: multi-party signing of media by QR or BLE
exchange (`cosign.request`, `cosign.response`), Android-only. The row is
already marked `shipped` (QR exchange landed in #246); what remains are the
row's folded items: #177 (cosign.request signs only after the owner approves
it on the phone) and its open PR #179.

## Slices

1. Fold PR #179: merge its head `row/177-cosign-approval` into
   `row/259-co-signing` with a merge commit (no rebase). Its plan is
   docs/plans/177.md; its tests come with it:
   `CosignRequestHandlerTest`, `KeystoreAliasGateTest`,
   `PromptEntryPointsTest`, `CoSignInitiatorFingerprintTest` and the
   updated handler, audit and approval-flow tests. Run `make test`.
2. Review fixes on the row PR: the anonymous co-sign instrumented test
   serves its request with no caller; an initiator QR names a
   desktop-created FIDO2 key (stored under `xkey_key_<id>`) by its
   fingerprint. `KeystoreManager.keyRowAlias` is the one key-row-to-alias
   mapping (picked by the row's stored public key), every hand-built
   `xkey_credential_`/`xkey_key_` alias goes through KeystoreManager, and
   `KeystoreAliasNamingChokePointTest` fails on a new hand-built one.
   Signing paths (local.sign, media auto-sign, the witness co-sign) stay
   on the general key: a FIDO2 credential never signs an arbitrary hash.
3. Merge main (merge commit) and cover the digest gate for every accepted
   `hashAlgorithm`: `CosignRequestHandlerTest` signs valid SHA-256/384/512
   digests exactly and only after approval, and refuses truncated, padded
   and other-length digests with no prompt.
4. Review fixes on two sites (test commit, then fix, for each):
   `local.deleteKey` deletes only user keys, and every Keystore removal it
   makes refuses (OPERATION_DENIED) an internal alias such as a store's
   protection key, PIV, the CA or an ephemeral key
   (`LocalDeleteKeyInternalAliasTest`); a desktop OATH code has no
   deadline only for HOTP, while a TOTP reply needs `expires_in` and is cut
   to its period (`DesktopCodeDeadlineTest`).
5. Review fixes on the credential delete (test commit, then fix): every
   Keystore removal of `local.deleteKey` and the legacy `deleteKey` goes
   through `deleteKeystoreAlias` (no raw `deleteByAlias` is left in
   Handler); a credential alias is removed by the audited
   `KeystoreManager.deleteCredentialKey`, with its Credential Provider
   metadata, both or neither: the metadata row comes out first and is put
   back if the material stays (a Keystore removal cannot be undone, so
   this is the order that keeps both on any failure). An internal-alias
   refusal writes a policy-denied audit record
   (`CredentialKeyDeleteTest`, `KeystoreManagerCredentialDeleteTest`).
6. Second review fixes on the credential delete (test commit, then fix):
   `deleteCredentialKey` runs under a per-alias lock shared by every
   handler and inside `persistAudited`, so a cancelled delete keeps both or
   neither and two deletes of one credential run one at a time. It writes
   back only a metadata row it removed itself, and only while the key is
   still in the Keystore. The order stays metadata first, then the audited
   key removal, not the "key first" order in the brief, because a removed
   Keystore entry cannot be put back if the metadata removal then fails.
   A test checks every main source file, so no other path removes passkey
   metadata or credential material.
7. Credential delete bounds and unknown key state: a delete takes a lock
   only for an alias that exists, and the lock entry is dropped when its
   last holder leaves, so many deletes of nonexistent IDs leave the lock
   map empty. When the Keystore cannot say whether the key is gone, the
   key counts as kept: the metadata row is written back and the delete
   fails. Tests: distinct nonexistent deletes leave no lock entry while
   concurrent deletes of one alias still serialize; a throwing removal
   with a failing alias listing keeps the metadata and fails.
8. Row PR from this branch closes #259 and supersedes #179; docs/SPEC.md
   keeps the row `shipped`.

## Out of scope

- BLE transport changes beyond what #179 carries.
- The desktop contract (the row is Android-only).
