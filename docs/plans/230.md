# #230: audit local.hmac and local.ecdh

## Objective

`local.hmac` and `local.ecdh` use a key but leave no audit entry. The
operation types `HMAC_REQUEST` and `KEY_DERIVATION_REQUEST` are defined and
labelled on the audit screen but never written. After this row every
successful HMAC (Keystore key or software key) writes one `HMAC_REQUEST`
entry and every successful ECDH writes one `KEY_DERIVATION_REQUEST` entry,
carrying the key id, the requesting device and the duration, the way
`local.sign` writes `SIGNING_REQUEST`.

## Slices

1. Failing tests (one commit):
   - `AuditLoggerDispatchTest`: `logHmacRequest` writes `HMAC_REQUEST`
     with key id, algorithm, device and duration; `logKeyDerivationRequest`
     writes `KEY_DERIVATION_REQUEST` the same way.
   - New `protocol/HmacEcdhAuditTest` drives `RequestHandler`:
     - `local.hmac` on a Keystore key writes one `HMAC_REQUEST` with the key id;
     - `local.hmac` on a software key writes one `HMAC_REQUEST` with the key id;
     - `local.ecdh` writes one `KEY_DERIVATION_REQUEST` with the key id;
     - missing params write no success entry;
     - no entry's details hold the MAC, shared secret, data or peer key.
2. Fix: `AuditLogger.logHmacRequest` and `logKeyDerivationRequest`;
   `handleLocalHMAC` calls the first on both return paths and
   `handleLocalECDH` calls the second after the operation succeeds.
3. Docs: `docs/audit-log/architecture.md` lists the two events.
4. Review fix (keyType): every key-use entry names the key's stored type
   (the audit screen filters on it), never the operation:
   - failing tests: `HmacEcdhAuditTest` asserts ECDH on a key stored as
     signing records "signing", HMAC records the stored type, a key with
     no metadata records "unknown"; `AuditKeyTypeChokePointTest` scans
     Handler.kt and fails on any key-use AuditLogger call whose keyType
     does not come from `auditKeyType`;
   - fix: one `RequestHandler.auditKeyType` helper (key row, then software
     key, then "unknown"); sign, decrypt, encrypt, HMAC and ECDH use it.

## Out of scope

- Failure entries for HMAC/ECDH (errors still surface on the wire only).
- Any other `Handler.kt` method (beyond the keyType sweep of slice 4),
  `AuditLog.kt`, `AuditLogActivity.kt`.
- Audit entries for the software-key symmetric encrypt/decrypt paths.
