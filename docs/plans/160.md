# 160: GATT server tests wait on signals, not settle sleeps

## Objective

Five `GattServer` test classes sleep for a fixed settle window
(`Thread.sleep(SETTLE_MS)`) before they check that something did not
happen, and poll with `Thread.sleep(10)` until something did. A settle
window is too short on a loaded CI runner and longer than needed
everywhere else. Each wait becomes a bounded wait on an observable
signal, with a timeout that fails the test. Every test keeps its
assertions.

## The signal

The server runs every coroutine on its `scope`, which the BLE tests
already treat as a seam (`ScopeDrain.kt`). A test puts a tracking
dispatcher under that scope in `setUp`. The dispatcher counts the
coroutine steps it has been handed and not yet finished:

- `awaitIdle` returns once no step is queued or running: every coroutine
  the server started is suspended (on a lock, a readiness, a timer) or done.
  A callback, a `Mutex.unlock` or a `complete` dispatches what it resumes
  before it returns, so after it the server is idle only once it has
  handled it. This replaces each settle sleep: "nothing is sent" is
  checked once the server has nothing left to run.
- `eventually` re-checks its condition each time a step finishes (and at
  least every 100 ms, for state another thread sets), up to its timeout.
  This replaces the `Thread.sleep(10)` polls.

No production change: `GattServer.kt` is left alone.

## Slices, in order (one commit per class, each green 20 runs in a row)

1. This plan.
2. `ScopeDrain.kt`: `TrackingDispatcher` and `trackScope(owner)`.
   `GattServerNotificationReadyTest` moves to it.
3. `GattServerCccdOrderTest`: the spacing between the row's events is
   `awaitIdle`, not 50 ms.

5. `GattServerEventOrderTest`.

   dispatcher, so the wait covers it reaching the Noise lock.

No test is added: the change is in how existing tests wait.
