# Plan: issue #287, deps-check fails on Bouncy Castle

## Objective

The scheduled scan on main (report #286) fails `make deps-check`:
`org.bouncycastle:bcprov-jdk18on` and `bcpkix-jdk18on` 1.86 are behind
1.87, and 1.87 is now past the 7-day settling window. Bump the shared
`bouncycastle` version so deps-check passes again.

## Cause

Bouncy Castle 1.87 was released and the settling window passed; the
catalogue still pins 1.86. No code defect.

## Slices

1. This plan.
2. `gradle/libs.versions.toml`: `bouncycastle = "1.86"` -> `"1.87"`
   (covers bcprov, bcpkix and bcutil, which share the version ref).
   Tests: existing suites, no new test, as the change is a version pin:
   - `make deps-check` prints no FAIL line;
   - `./gradlew :app:testDebugUnitTest` passes;
   - `make it-jvm-test` passes.
   If 1.87 breaks a test, fix the test or the call site, test first.

## Main image builds

After the 1.87 bump merged, the integration and toolchain image builds on
main failed at 10:27Z: the apt package mirror returned HTTP 500 during
`apt-get update` in `build/docker/devcontainer/Dockerfile`. Bouncy Castle
1.87 was not the cause and stays. No apt-get step retried, so one transient
mirror error failed the whole image build.

Fix: the `fetch` and `base` stages write `Acquire::Retries "5";` to
`/etc/apt/apt.conf.d/80retries` before their first `apt-get`; `toolchain`
and `integration` are FROM base and inherit it, so every `apt-get update`,
`upgrade` and `install` retries. The integration stage keeps its strict
`APT::Update::Error-Mode=any` update and the APT_INDEX_SUM flow
(`make image-tag-test` passes). CI builds the images.

Test: the value lives in `build/docker/devcontainer/apt-retries.conf`, which
the fetch and base stages COPY; `make apt-retry-test` (in `make lint-gates`)
fails when a stage runs apt-get without it, and runs apt-get update with it
against a loopback stub mirror that recovers after HTTP 500s (passes), always
returns 500 (fails) and, with `Acquire::Retries 0`, recovers too late (fails).
