# Plan: store sync merge rules (row 319)

## Objective

Sync merges never undo a local decision: deleted passwords and OATH
credentials stay deleted, synced certificates never become trust anchors,
synced OATH copies never overwrite a stored secret, and malformed sync items
are errors. All of it lands on one database schema 14.

## Slices, in order

1. Merge main into the row branch.
2. Password sync (carried): deletion records, clock clamp for peer times far
   ahead, sync writes only passwords it would send, migration test, docs.
   Tests: PasswordSyncTest, XKeyDatabaseMigrationTest.
3. Trust-store sync (carried): synced certificates stored as synced and never
   anchors, each certificate merged alone, one audit entry per sync.
   Tests: SyncedTrustAnchorTest, TrustStoreSyncHandlerTest,
   RemoteSyncClientTest, SyncEngineTrustStoreTest.
4. OATH sync (carried): oath_deletions records, synced copy never overwrites
   a stored secret or code parameters, migration test.
   Tests: SyncEngineMergeOathTest, XKeyDatabaseMigrationTest,
   XKeyDatabaseRoomUpgradeTest.
5. Sync decode errors (carried): malformed PEM or timestamp rejects the item.
   Tests: SyncCodecTest, PasswordSyncTest, SyncEngineTrustStoreTest.
6. One schema 14: a single 13 to 14 migration creating both the password
   deletion table and oath_deletions, both entities and DAOs registered, the
   exported 14.json matching, migration tests covering passwords, OATH rows
   and both empty deletion tables. The migration code became one while
   resolving the OATH delete-record pick, which conflicted on it; the
   reconcile commit then brings the exported 14.json and the identity hash
   the upgrade test pins.
7. Adapt any carried test that names a symbol absent on this branch, as a
   separate test commit.

## Out of scope

- OATH store hardening from other rows (only the smallest edit a carried
  pick needs).
- Any branch content not listed above.
