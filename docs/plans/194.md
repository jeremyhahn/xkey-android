# Plan #194: the passkey provider honours its enable switch

## Objective

docs/SPEC.md promises a passkey provider "with an enable setting". Today the
Settings switch only stores the value: `XKeyCredentialService` hands every
begin-create and begin-get request to the handlers. After this row, with the
switch off the provider offers no create entries and no credential entries to
the system picker; with it on, behaviour is unchanged.

## Design

- **Where the gate sits.** In front of the handlers, in the service.
  A small `CredentialProviderEnableGate` (in `CredentialProviderSettings.kt`)
  takes `isEnabled: suspend () -> Boolean` and wraps each begin call: when the
  setting is off it answers an empty `BeginCreateCredentialResponse` /
  `BeginGetCredentialResponse` without calling the handler, so nothing is
  looked up in Room and no PendingIntent is built. The handlers stay
  unchanged, so their instrumented tests, which call them directly, need
  no setting.
- **How tests inject the setting.** The gate takes the read as a lambda.
  `CredentialProviderSettingsRepository` gets an optional `DataStore`
  constructor parameter (defaulting to the app's store) and an
  `isEnabled()` read, so a JVM test can back it with an in-memory
  `DataStore<Preferences>`. No Android storage in the JVM tests.
- **Default when nothing is stored: off.** The stored default stays
  `false`, as the Settings screen and `CredentialProviderSettingsRepositoryTest`
  already document it: a user turns the provider on in xKey and then selects
  it in system settings. No change argued.
- An "off" begin call is a normal, empty answer, not an error, so the system
  picker simply shows no xKey entry.

## Slices

1. This plan.
2. Failing tests, `CredentialProviderEnableGateTest` (JVM):
   - setting off: begin-create returns no create entries and never calls the
     create handler;
   - setting off: begin-get returns no credential entries although the get
     handler would return an entry for a stored passkey of that RP;
   - setting on: begin-create and begin-get return the handlers' entries;
   - nothing stored: a repository over an empty store reads off, and the gate
     then answers empty (the documented default).
3. The fix: gate + repository read, service wired through the gate. Tests green.
4. Docs and e2e: `docs/passkey-provider/architecture.md` describes the switch
   and its default; `WebAuthnE2ETest` turns the setting on in setup (and
   restores it after). The SPEC row stays shipped and unchanged.

## Gates

Credential unit tests, `compileDebugAndroidTestKotlin`, lint gates.

## Out of scope

Changing the default, the Settings UI, the handlers' own behaviour, the
final (non-begin) create/get calls: those run only from an entry the begin
phase offered.
