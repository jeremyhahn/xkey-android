# Plan: SPEC row remote-key-access (#256)

## Objective

`remote.*` from phone to desktop reaches the xkmsd backends through the
desktop `Bridge`: key operations, sync and PIV; a router sends `remote.*` to
the desktop and `local.*` to the phone. This row folds #141 (remote.oathAdd,
remote.oathGenerate) and the share methods of #144 (remote.sharePublicKey,
shareSymmetric, importSharedKey), carried by PRs #159 and #170.

## Slices, in order

1. **Fold PR #159** (`row/141-remote-oath`, merge `--no-ff`). It conflicts
   with main's #175, which bound the share client's sends another way.
   - Main (#175): transports implement `MessageSender`, plus
     `confirmedConnection()` and `sendEncryptedMessageOn(ConfirmedConnection)`;
     `RemoteShareClient` and `DesktopSessions` send only through the scoped call.
   - #159: transports no longer implement `MessageSender`; the only send path
     is a `SessionSender` bound to the connection that authenticated the peer
     (`ConnectedDesktop`, `boundSender()`); every `remote.*` client is built
     from a `ConnectedDesktop`.
   - Resolution: keep #159's rule (no unbound send on a transport). Each bound
     `SessionSender` also implements main's scoped API: `confirmedConnection()`
     answers its own connection's `confirmedHere()` only while that connection
     is current, and `sendEncryptedMessageOn(c)` refuses with
     `ConnectionChangedException` unless `c.connection` is the bound
     connection, then sends through the transport's scoped admission. The
     transports' `confirmedConnection`/`sendEncryptedMessageOn` lose
     `override` and stay as the binders' internals. `StreamPairingSession.admit`
     keeps both checks: `expected` must be `sameAs(confirmedHere())`, and a
     phone-initiated frame needs `activeConnection === this`. Main's
     `XKeyGattService` `activeTransport` (share client, desktop sessions) takes
     the `ConnectedDesktop` sender instead of the transport.
   - Conflicted files: GattServer, XKeyGattService, RemoteSyncClient,
     StreamPairingSession, OathActivity, DesktopSessionTrackerTest,
     GattServerReconnectTest, StreamPairingSessionRevocationTest,
     docs/remote-key-access/architecture.md.
   - Tests: #159's RemoteOathClientTest, ConnectedDesktopBindingTest,
     TcpConnectedDesktopBindingTest, UsbConnectedDesktopTest,
     OathDesktopActionsTest, DesktopCodeDeadlineTest, and main's
     RemoteShareClient/DesktopSessions tests, which now go through a bound sender.
2. **Fold PR #170** (`row/144-remote-share`, merge `--no-ff`). Its branch
   does not contain #175, the squash of its own earlier commits, so expect
   add/add conflicts in RemoteShareClient, DesktopSessions,
   DesktopSectionRefresh, LoadZeroedOnCancel and their tests: keep the newer
   #170 side where it extends #175, and build its clients on slice 1's
   `ConnectedDesktop`.
3. **Router and acceptance check**: a test that `remote.*` goes to the
   desktop and `local.*` to the phone on every transport; mark the row
   shipped in docs/SPEC.md.

Each slice runs the unit tests of the packages it touches
(remote, transport, tcp, usb, ble, ui) and `make integration-test-<feature>`
for remote-key-access.

## Out of scope

- Symmetric-key wrap for remote.shareSymmetric beyond what #170 carries
  (no wrap path matches the desktop's BYOK import, per #175).
- USB PasswordVault verbs (#55, blocked).
