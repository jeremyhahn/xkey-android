# Plan: #196 verified badge names the matched signer

## Objective

The name beside a signer's badge comes from the key the signature was
checked against, never from the file. `SignerVerification.verify` picked
`entry.signerName ?: contact.name`, so a file signed by contact "Bob" that
embeds signerName "Alice" showed verified "Alice". The embedded name is
shown only as a marked claim, on its own line.

## Name precedence per status

| Case | displayName | claimedName |
|---|---|---|
| VERIFIED, contact match | contact name | embedded name if it differs |
| VERIFIED, local key match | local key label | embedded name if it differs |
| FAILED, contact or local key match (bad signature, hash mismatch, error) | matched name | embedded name if it differs |
| FAILED, hash mismatch with no match | embedded name, else fingerprint prefix | null |
| UNKNOWN (no match) | embedded name, else fingerprint prefix | null |

## Result shape

`Result(status, displayName, claimedName: String? = null)`. `displayName`
stays, so `FileOperationActivity` compiles unchanged and picks up the new
precedence. The viewer carries `claimedName` into `VerificationResult` and
shows it below the badge row as `Claims: <name>` (`verified_viewer_claims`).
