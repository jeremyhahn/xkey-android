# Plan: PIV Ed25519 and X25519 slot keys (PR 347)

## Objective

PIV slots hold Ed25519 and X25519 keys made by the Android Keystore in secure
hardware (the TEE, Android 13 and later), never a software key. Below Android
13, or when the Keystore cannot make the curve or the key is not in secure
hardware, generation fails with `PivAlgorithmUnavailableException` and the
slot keeps what it had. An X25519 key only agrees and never signs. The wire
handlers, the PIV screens and the docs follow.

## Slices, in order

1. Tests first: the Ed25519/X25519 slot key contract.
   Tests: PivSlotTest, PivKeyManagerTest.
2. Secure-hardware slot keys: `PivAlgorithm` gains `pivAlgorithmId`
   (ES256 0x11, ES384 0x14, RS2048 0x07, Ed25519 0xE0, X25519 0xE1),
   `canSign`, `canAgree`, `minSdk`; `PivKeyManager` checks the API level and
   the key's security level (new trailing `securityLevelOf` parameter),
   signs with the slot's algorithm, adds `agree` for X25519;
   `PivPublicKeyEncoding` gives the PIV tag 0x86 value.
   Tests: PivSlotTest, PivKeyManagerTest, PivPublicKeyEncodingTest.
3. Real Keystore check on a device and architecture notes.
   Tests: PivCurve25519KeystoreTest (instrumented, skipped without Android 13
   secure hardware).
4. Handlers accept the curve 25519 names and PIV ids, answer `algorithm_id`
   and `public_key_raw`, refuse an unavailable algorithm with
   `FEATURE_UNAVAILABLE` and an X25519 sign with `INVALID_ALGORITHM`.
   Tests: PivHandlerTest.
5. PIV screens offer Ed25519 and X25519 only on Android 13 and later and show
   the PIV algorithm id. Tests: PivActivityUiTest.
6. Dialog tests pick the algorithm by name. Tests: PivActivityUiTest.

## Merging with other key algorithm work

Open PRs for key algorithm parity and post-quantum keys add the same 4th
`PivAlgorithm` parameter (`pivAlgorithmId`) with the same ids. This branch
keeps it 4th with that name; every newer parameter has a default and comes
after it, and algorithms are chosen by name (`PivAlgorithm.ED25519`,
`fromStoredName`, `fromPivAlgorithmId`), never by index, so whichever lands
second merges the enum entries only.
