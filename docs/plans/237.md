# #237: bound the CA bundle fetch

## Objective

`CABundleFetcher.fetchBundle` (`/acme/ca-bundle`) gets the same limits
`BootstrapClient` already applies to `/v1/ca/bootstrap`, as the
`trust-store-bootstrap` architecture describes: the body is read up to
`MAX_RESPONSE_SIZE` (1 MB, counted on the decoded stream so a compressed
reply is bounded too), and a bundle with more than
`MAX_BUNDLE_CERTIFICATES` (64) certificate blocks is refused before any
block is parsed. Both failures raise `CABundleFetchException`.

## Slices

1. This plan.
2. Failing tests in `CABundleFetcherTest` on the existing interceptor
   harness:
   - a body of 1 MB + 1 byte throws `CABundleFetchException`;
   - a body of exactly 1 MB (one certificate plus comment padding) parses;
   - a gzip body that inflates past 1 MB throws (the response body is the
     decoded `GzipSource`, as OkHttp's bridge hands it to the caller);
   - 65 certificate blocks throw before parsing;
   - 64 certificate blocks parse all 64.
3. The fix in `CABundleFetcher`:
   - `readBoundedBody` reads `byteStream()` in 8 KB chunks and throws past
     1 MB (mirrors `BootstrapClient.readBoundedBody`);
   - `parsePEMBundle` counts `BEGIN CERTIFICATE` blocks first and throws
     above 64;
   - the constants are declared once in `CABundleFetcher` with a comment
     naming the `BootstrapClient` ones (the two packages stay decoupled);
   - class KDoc states both limits.

Existing `CABundleFetcherTest` cases stay unchanged.
