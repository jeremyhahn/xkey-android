# 358: desktop backup service and the USB accessory gate

## Objective

Cover the phone-initiated desktop backup entry points of `XKeyGattService`
(`createDesktopBackup`, `restoreDesktopBackup`, `listDesktopBackups`,
`latestStoredBackupId`) and the native USB gate in `onUsbAccessoryAttached`.
`RemoteBackupClientTest` already covers the client's wire format and its own
buffer zeroing; these tests cover what the service adds: the desktop lookup,
the `BackupStore` record, the id handed back and the password zeroing around
both.

## Slices

1. `ble/DesktopBackupServiceTest` (Robolectric, service built without
   `create()`, a mockk `TcpHsmServer` set on the private `tcpHsmServer` field
   answering with a `ScriptedMessageSender` desktop, the real `BackupStore`):
   - no desktop: create, restore and list throw IllegalStateException, send
     nothing, store nothing; create and restore zero the password;
   - create success: decoded result, envelope stored under the desktop's id,
     `latestStoredBackupId` names it, label starts with `phone-`, password
     zeroed;
   - create on an error reply, on a sender that throws and on a store that
     cannot write (a plain file named `backups`): the error propagates, the
     password is zeroed, the store is unchanged;
   - restore: unknown id throws "No stored backup", sends nothing, zeroes
     the password; a stored id sends that envelope as `backup_data`; an error
     reply and a thrown send propagate with the password zeroed;
   - list returns the desktop's backups and sends no password;
   - a create reply with no `backup_id`: the id returned can be restored.
2. `ble/UsbAccessoryGateTest` (Robolectric, `requestHandler` and
   `usbHsmSettingsRepository` set by reflection, the repository a mockk with
   `coEvery { getSettings() }`): native USB off and a null repository open
   nothing and leave the slot inactive; native USB on reaches the open
   (`mockkConstructor(UsbAccessoryServer::class)` with `connect` stubbed, so
   no `UsbManager` is touched, and the test `FakeAndroidKeyStore` installed
   for the seal store's Keystore cipher); a null request handler and an already-active
   slot (a mockk slot set on `usbServerSlot`) return before the settings are
   read and launch nothing. Negative cases join the gate's job on
   `serviceScope` (every child but the attach path's observer) first.
3. Test-first fixes in `XKeyGattService.kt` for each finding below.

## Findings

- A create reply with no `backup_id`: `BackupStore.store` keeps the envelope
  under a generated id, but `createDesktopBackup` drops that return value
  and hands back the blank id, so the dialog's Snackbar names no backup and
  a restore by the returned id finds nothing. Fixed: the service returns the
  result under the id the store used.
- A store that fails after a successful create leaves the desktop holding a
  backup the phone did not keep. The protocol has no delete for a desktop
  backup, so the service cannot undo it; the IOException reaches the
  dialog. Not fixed here.

## Out of scope

The client's wire format and request-buffer zeroing (`RemoteBackupClientTest`),
the dialogs, the USB session itself (`UsbAccessoryServer*Test`).
