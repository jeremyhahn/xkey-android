# 254: SPEC row hardware-backed-keys

## Objective

Close the `hardware-backed-keys` row of docs/SPEC.md: `local.*` crypto on
StrongBox or TEE, with `local.getCapabilities` telling the truth. The one
open gap is #199: Keystore key agreement (`PURPOSE_AGREE_KEY`) exists only
from API 31, yet minSdk is 28 and ECDH was advertised everywhere.

## Slices, in order

1. **Fold #206** (row/199-ecdh-capability-api31, plan docs/plans/199.md):
   merge the branch as built. It adds `KeystoreCapabilities` (API floors),
   advertises ECDH only from API 31, refuses `local.ecdh` below 31 with a
   plain `ECDH_FAILED`, sets `PURPOSE_AGREE_KEY` only from 31, and stops
   advertising Ed25519. Tests: `KeystoreCapabilitiesTest`,
   `RequestHandlerLocalKeyFamilyTest`, `RequestHandlerErrorPathTest`,
   `KeystoreManagerGeneralKeysTest` (fail before, pass after).
2. **SPEC row**: the row stays `shipped`; its text says ECDH and
   `PURPOSE_AGREE_KEY` are API 31+.

## Out of scope

- Any other `local.*` verb change; the row's other verbs shipped on main.
- Instrumented (`make integration-test`) runs: they need a device, CI has it.
