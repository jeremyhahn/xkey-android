# 352: TPM attestation parsing and quote binding

## Objective

TPM enrollment decides which desktop keys this phone's certificate authority
signs, and every byte it parses comes from the desktop. This row gives the
parsers direct JVM tests and binds the PCR values the desktop reports to the
quote it signed.

## Slices, in order

1. `TpmPublicAreaTest`: RSA exponents, keyBits and modulus refusals; P-256,
   P-384, P-521; unsupported curve and type; symmetric definition and ECC KDF
   read past; `name()` per nameAlg; every prefix refused.
2. `TpmQuoteBindingTest` and `TpmTestStructures` helpers: RSA-PSS and P-384
   quotes, selection count and bitmap bounds, every prefix; binding: a matching
   digest verifies, a changed value, another bank, a missing index refused.
3. `TcgCsrIDevIDBoundsTest`: every prefix, trailing bytes, unreadable public
   areas, certify by an unrestricted attester.
4. Each bug: a failing-test commit, then the fix.

## Out of scope

The wire format; which PCRs are requested; key-size and trailing-byte policy.

## Findings

Bug, fixed (failing test, then fix): the PCR values were not bound to the
quote. `TpmAttest.parse` skipped the TPML_PCR_SELECTION and
`TpmQuoteVerifier.verify` never compared the pcrDigest, so enrollment stored
whatever values the desktop reported beside a genuine quote as the device's
initial PCRs, and never checked the quote covered the requested bank. The
parser now keeps each selection; a `verify` overload taking the bank and the
values checks one non-empty selection, its bank, that its indices are the
reported ones and that pcrDigest is the scheme hash of the values in index
order. Enrollment calls it; the four-argument `verify` stays for callers that
keep no PCR values.

Recorded (asserted as main behaves; policy questions, not changed):

- `TpmPublicArea` accepts trailing bytes; they stay in `raw` and change the Name.
- An off-curve ECC point and zero-length x and y parse (the JDK EC key factory
  does not check the point); no signature verifies under them.
- A 1024-bit RSA key parses: there is no minimum key size.
- RSA-PSS fixes the salt at the hash length; a maximum-salt PSS signature,
  which some TPMs produce, is refused.
- `TcgCsrIDevID.parse` ignores bytes after the signature.
- `csr.iak` / `csr.idevid` throw `TpmStructureException`; only
  `verifySelfSignature` converts it, and enrollment reads them after it.
- `TpmCertifyVerifier.verify` checks no attester attribute and accepts an
  unrestricted attester; enrollment relies on `verifySelfSignature`.
- `TpmQuoteVerifier.verify` lets `name()`'s `TpmStructureException` escape for
  an unsupported nameAlg; enrollment refuses such an IAK first.
- The host JDK has no `SHA256withRSA/PSS`; the PSS tests register Bouncy Castle.
