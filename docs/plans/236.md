# Plan: Noise transport nonces follow the Noise rules (#236)

## Objective

`NoiseSession.decrypt` advances `recvNonce` before the AEAD check, so one
frame that fails authentication (a corrupt or forged frame) moves the
receive counter past the nonce the peer will use next: every later genuine
frame fails and the session is dead. `BleClient` already drops such a frame
and expects the nonce unchanged. The Noise framework's DecryptWithAd leaves
`n` unchanged on an authentication failure, and reserves `n = 2^64-1`
(`-1L` as a signed Long): no message may be encrypted or decrypted with it.

## Slices, in order

1. This plan.
2. Failing tests, committed alone:
   `app/src/test/kotlin/com/automatethethings/xkey/ble/NoiseSessionTransportNonceTest.kt`,
   on the existing harness (a `NoiseSession` responder against
   `NoiseInitiatorSession`, through a real XX handshake):
   - a frame with one flipped ciphertext bit fails to decrypt, and the
     genuine frame for the same nonce still decrypts after it;
   - three frames after a failure decrypt in order;
   - a session whose send counter is at the reserved value refuses to
     encrypt, and one whose receive counter is there refuses to decrypt,
     with `NoiseException` (counters set through a test seam, never by
     looping); one below the reserved value encrypts once, then refuses.
3. The fix in `NoiseSession.kt`:
   - `decrypt` builds the nonce from `recvNonce`, runs `doFinal`, and
     increments `recvNonce` only after it succeeds;
   - `encrypt`, `decrypt`, `encryptAndHash` and `decryptAndHash` throw
     `NoiseException` when their counter is at the reserved value;
   - `setTransportNoncesForTest`, a test seam next to
     `secretArraysForTest`.
4. `docs/noise-pairing/architecture.md` Transport Encryption states both
   rules.

## Out of scope

- The nonce layout (4 zero bytes + 8-byte little-endian counter).
- `BleClient.kt`, `GattServer.kt`, `StreamPairingSession.kt`: their
  drop-or-teardown handling stays as is (open PRs edit the first two),
  including `NoiseInitiatorSession`'s own counters.
- The zeroization paths (`reset`, `splitSymmetricState`, `mixKey`).
