# #180: a signature never shows as verified without a real check

## Objective

Two bugs share one rule: a signer is verified only when the stored content
hash matches the file *and* the signature checks against a public key we
hold.

1. Trust by association. `VerifiedMediaViewerActivity.verifyEntry` and
   `FileOperationActivity.verifySignatures` match a local key row with no
   public key (`publicKeyDer == null`) when its `keyId` equals the entry's
   `keyFingerprint`, then report the signer verified with no signature
   check. Both values come from the file under test. Such a key must never
   match: the signer is unknown.
2. Copied signature block. `FileOperationActivity.performVerify` hashes the
   file but `verifySignatures` checks the signature over the stored
   `contentHash` alone, so an in-band block copied onto another file
   verifies. The in-band path must check
   `MediaHasher.contentHashMatchesUri(..., SignatureSource.IN_BAND)` first,
   as the viewer and the sidecar path do; on a mismatch every entry fails.

## Slices (commits, in order)

1. This plan.
2. Refactor, behaviour unchanged: `media/SignerVerification.kt` holds the
   per-entry decision (today's rule, trust-by-association included); both
   activities call it and keep their own result types and UI text.
3. Failing tests: `media/SignerVerificationTest.kt` with real EC P-256
   keys. Null-key row whose keyId equals the fingerprint gives UNKNOWN
   (fails on slice 2); valid key + signature + hash match gives VERIFIED;
   hash mismatch, corrupted signature, invalid contact signature give
   FAILED; valid contact signature gives VERIFIED; no match gives UNKNOWN.
4. Fix: drop the null-key match; `performVerify` checks the in-band content
   hash and passes the result in.
5. Docs: both features' `architecture.md` state the rule.

## Out of scope

- strings.xml, Handler.kt, AuditLogger.kt, ble/ and remote/ (open PRs).
- Desktop-side signing and the sidecar format.

## r2: mismatch fails before signer lookup

Codex found two gaps in r1. First, `SignerVerification.verify` returned
UNKNOWN for a signer matching no contact and no local key before it read
`contentHashMatches`, so a block copied from an unknown signer showed as
"Verification complete" and was audited as success. Second, no flow test
covered the in-band hash check, and `FileOperationFlowTest.embedSignature`
still stored the whole-file hash, which an in-band check rejects.

1. Failing tests: `SignerVerificationTest` mismatch cases with no matching
   signer and with a null-public-key row (FAILED, never UNKNOWN);
   `FileOperationFlowTest` copied-block regressions, for a contact (the
   original verifies, the copy fails) and for an unknown signer.
2. Fix: `verify` returns FAILED on a mismatch before any lookup. On a
   mismatch the embedded path in `performVerify` also adds the sidecar
   path's "Content hash mismatch" line, so the header and the audit entry
   fail even when the block has no entries. `embedSignature` stores the
   canonical hash.

Caller sweep: the viewer audits `all VERIFIED` and shows each entry's
status, so a mismatch fails in both. The sidecar path already failed in
the UI and the audit. The embedded path now fails in both.

## r3: producers hash canonical content

Codex found that the in-band check now accepts only the canonical hash, but
`MediaSigningService.handleNewMedia` stored the whole-file `hashUri` before
embedding the signature, so an untouched auto-signed JPEG with APP metadata
failed with "Content hash mismatch" and a failed audit entry.

1. Refactor, behaviour unchanged: the stored hash moves to `AutoSignHash`.
2. Failing test: `AutoSignRoundTripTest` signs a camera JPEG (JFIF + EXIF)
   with the automatic signer's hash, embeds an XMP APP1 segment and runs the
   share screen's check (IN_BAND `contentHashMatches`, then
   `SignerVerification.verify`).
3. Fix: `AutoSignHash.contentHash` is `MediaHasher.hashCanonical`.

Producer sweep: the automatic signer now hashes canonical content (fixed);
the manual sign screen (`FileOperationActivity` sign) already uses
`hashCanonicalUri`; both co-sign paths (`CoSignActivity.signAsWitness` and
`Handler.handleCosignRequest`) sign a hash taken from the request and never
hash the file; the sidecar is written from the same data, and SIDECAR accepts
the canonical hash. No export path produces a signature.
