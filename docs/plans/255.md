# Plan 255: SPEC row key-sharing

## Objective

Row `key-sharing` of docs/SPEC.md: `local.sharePublicKey`,
`local.shareSymmetric`, `local.importSharedKey`; per-key, per-peer sharing
policies managed from the key detail screen. One branch, one PR that closes
#255 and leaves the row `shipped` in docs/SPEC.md.

The row already reads `shipped` on main. The open work is the folded items:

- #193 (PR #211, branch `row/193-grant-order`): grants, withdrawals and
  key-wide clears apply in user-action order, through one KeyPolicyStore.
- PR #215 (branch `row/174-unpair-drops-grants`): follow-up to the unpair
  grant cleanup, held for #211.

## Review map

One line per test file this row changes: the production unit it covers and
the behaviour it asserts. Unit tests are under `app/src/test/kotlin/...`,
on-device tests under `app/src/androidTest/kotlin/...` (package paths below
start at `xkey/`).

### Unit tests

- `StartupKeyDeletionReplayTest`: `XKeyApplication` startup deletion replay; a store that fails to open neither crashes startup nor drops an owed delete.
- `auth/PromptEntryPointsTest`: `PromptOwnership`; every prompt raiser goes through it (source scan).
- `credential/PasskeySignCounterHandlerTest`: passkey sign counter; one counter shared per credential across handlers.
- `credential/handler/AssertionSignCountTest`: assertion handler; queued assertions sign strictly increasing counters.
- `crypto/Ed25519ValueReadFailureTest`: `KeystoreManager.ed25519Read`; a value read that fails after `contains()` passes (SecurityException or GeneralSecurityException) is `KeyPresenceUnreadableException` through `userKeyGeneration`, `keyMaterialGeneration`, `getEd25519PrivateKey` and `deleteUserKeyGeneration`; a delete from either key screen is refused, nothing recorded; no Ed25519 preference read bypasses the helper (source scan).
- `crypto/FileDecryptDeletedKeyTest`: `FileEncryptor` decrypt; a tombstoned key decrypts nothing.
- `crypto/FileEncryptorEphemeralKeyLeakTest`: `FileEncryptor`; the ephemeral key is deleted by its exact alias, and a failed delete fails the encryption.
- `crypto/KeyIdWriteValidationTest`: `KeystoreManager` key writes; an empty key id is rejected.
- `crypto/KeyPresenceUnreadableTest`: `KeystoreManager` presence; three-way present/absent/unreadable, never a fallback on unreadable.
- `crypto/KeystoreManagerPivAliasTest`: `KeystoreManager` alias resolution; PIV slot aliases never resolve as a raw user alias.
- `crypto/LegacyRecordInvariantTest`: `SoftwareKeyStore` legacy records; a metadata shape it cannot place fails closed.
- `crypto/SoftwareKeyDeleteReplayTest`: `SoftwareKeyStore.deleteGeneration`; a failed material unlink keeps the record and its replay finishes; an unreadable metadata-only record refuses the delete.
- `crypto/SoftwareKeyIndexTest`: `SoftwareKeyStore` index; the metadata scan is cached until a write.
- `crypto/SoftwareKeyStorePresenceTest`: `SoftwareKeyStore.presence`; three-way presence.
- `crypto/SoftwareKeyStoreReadBypassTest`: `SoftwareKeyStore`; every record read goes through `readRecordFile` (source scan).
- `crypto/SoftwareKeyStoreRecoveryTest`: `SoftwareKeyStore`; an unparseable legacy record and a metadata-only leftover are recovered by replay.
- `crypto/SoftwareKeyStoreSearchProbeTest`: `SoftwareKeyStore`; a directory that lists but cannot be searched is unreadable.
- `protocol/CosignRequestHandlerTest`: co-sign handler; co-sign runs only after the owner's approval through the prompt queue.
- `protocol/GenerationEchoTest`: `RequestHandler`; the key generation is echoed verbatim.
