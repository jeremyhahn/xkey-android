# Plan: PIN and OATH handler errors (#133)

## Objective

Four local.* handlers return the wrong result. Fix each one, with a failing
unit test committed before its fix.

## Slices, in order

1. **PIN lockout.** `local.pinSet` and `local.pinResetLockout` map a
   `PinLockedException` (locked SO PIN) to INTERNAL_ERROR. They should return
   PIN_LOCKED, as `local.pinChange` already does.
   Test: `PinOathHandlerErrorsTest` with a mocked `PinManager` that throws
   `PinLockedException`, checking for PIN_LOCKED.
2. **PIN length.** A new PIN outside 6 to 63 UTF-8 bytes
   (`PinHasher.validatePinLength`) makes `PinManager` throw
   `IllegalArgumentException`, which comes back as INTERNAL_ERROR.
   `local.pinSet` and `local.pinChange` check the new PIN's length before
   calling the manager and return INVALID_PARAMS.
   Test: 5-byte and 64-byte new PINs return INVALID_PARAMS and never reach
   the manager.
3. **oathRemove of an unknown id.** The handler deletes and returns
   `deleted: true` even when no credential has that id. With no row, it
   returns `deleted: false` (no new error code; the result is the same shape).
   Test: DAO `getByOathId` returns null, so `deleted` is false and nothing is
   deleted or audited.
4. **otpauth percent-encoding.** `SyncEngine.mergeOath` builds the
   `otpauth://` URI with the raw issuer and account, so a space, `&`, `?`, `#`
   or `/` breaks the parsed label and query. The builder moves to an internal
   `buildOtpauthUri` and percent-encodes issuer and account (RFC 3986, space
   as `%20`).
   Test: `SyncEngineOtpauthUriTest` for an issuer and account with reserved
   characters.

## Out of scope

- An issuer containing `:` still splits the label wrongly once the path is
  decoded by `OathRepository.parseLabel`; the `issuer` query parameter wins,
  so the stored issuer is right, but the account may not be. Left alone.
- No wire method names, no SPEC wording, no go-xkms change.
