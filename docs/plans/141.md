# Plan: remote OATH client (#141)

## Objective

Let the phone store an OATH credential on the paired desktop
(`remote.oathAdd`) and show the current code of a desktop-stored credential
(`remote.oathGenerate`), using the go-xkms wire shapes in
`pkg/pairing/protocol_oath.go` at tag `xkey/v0.64.2-alpha`. No SPEC.md change
and no other wire change.

## Slices

1. `RemoteOathClientTest`: params shape (`credential` object; `credential_id`),
   go `omitempty` handling, escaping, secret zeroing (caller chars and body),
   validation before send, strict result parsing (wrong types, missing fields,
   `success: false`, non-digit code, string/negative/fractional `expires_in`),
   desktop error and timeout, shared request-ID counter, Base32 vectors.
2. `remote/RemoteOathClient.kt` until slice 1 passes. IDs from a companion
   counter above 5,000,000 (no cross-client counter exists; the others use
   1M-4M).
3. `OathDesktopActionsTest`: copy sends `remote.oathAdd` and stores the
   desktop ID; desktop code sends `remote.oathGenerate` and returns code plus
   expiry; no desktop: no menu entries, nothing sent.
4. `OathDesktopActions` (in `ui/OathActivity.kt`), context-menu entries,
   code dialog, strings in `strings_oath.xml`. The activity binds
   `XKeyGattService` without auto-create; a small
   `XKeyGattService.remoteOathClient()` accessor (outside the file map) hands
   out a client on the active transport.
5. `docs/remote-key-access/architecture.md` lists both methods; `make test`.

## Out of scope

- Listing or deleting desktop credentials (`remote.oathList` etc.).
- Marking synced credentials as desktop-stored: the desktop ID is known only
  from an oathAdd reply made on this phone.
- Any change to RemoteKeyClient, RemoteSyncClient, RemoteBackupClient or SPEC.md.
