# 221: audit OATH and password syncs

## Objective

The `audit-log` SPEC row records security events; the `store-sync` row moves
OATH secrets and passwords between phone and desktop. Neither direction of an
OATH or password sync leaves an audit entry today. After this row, every OATH
and password sync, inbound (`local.syncOATH`, `local.syncPasswords`) and
outbound (`RemoteSyncClient.syncOath`, `syncPasswords`), records exactly one
entry, success or failure, with no secret, password, site or user name in it.

## Slices

1. Plan (this file).
2. Failing tests, committed before the fix:
   - `protocol/SyncAuditTest`: `local.syncOATH` records one
     `OATH_SYNC_PERFORMED` entry with success, the caller device id and name
     and the merge counts, and its response JSON is unchanged;
     `local.syncPasswords` records one `PASSWORD_SYNC_PERFORMED` entry whose
     details hold no password, site or user name; a locked store answers
     `PASSWORD_STORE_LOCKED` and records one failed entry; a failing OATH
     merge records one failed entry; with the audit logger not initialized
     both handlers answer as before.
   - `remote/RemoteSyncClientTest`: `syncOath` and `syncPasswords` each record
     one outbound entry; `syncAll` with a locked vault records the failed
     password leg and still syncs the other stores; a peer error records a
     failed entry and still throws; with the logger not initialized the
     client answers as before.
3. The fix:
   - `AuditOperationType.PASSWORD_SYNC_PERFORMED` (stored by name, no Room
     migration), its audit-screen label and string;
   - `AuditLogger.logOathSyncPerformed` widened with defaulted direction,
     counts, success and error parameters; new `logPasswordSyncPerformed`;
   - inbound entries in `handleSyncOATH` / `handleSyncPasswords`, carrying
     the caller device id and paired name; outbound entries in
     `RemoteSyncClient`, which takes an optional peer id and name.
4. Fix round (Codex): `RemoteSyncClient.audited` splits each outbound leg
   into a send phase and a merge phase, so a merge that throws after the
   desktop acknowledged items records the acknowledged pushed count in the
   failed entry (0 only when the send fails). Tests in
   `RemoteSyncClientTest` for the OATH and password legs, committed first.
5. Fix round (Codex): both inbound handlers run through one audited path,
   `RequestHandler.auditedInboundSync`. The peer id comes from the
   connection, and the paired-name lookup runs inside that path (null when
   the store throws). `SyncAuditTest` makes the paired store unreadable and
   expects both syncs to run and be audited; that test is committed first.
6. Docs: `docs/audit-log/architecture.md` and
   `docs/store-sync/architecture.md` list the sync events.
