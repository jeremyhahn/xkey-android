# 217: recent activity on the home screen

## Objective

The `audit-log` feature promises "audit screen and recent activity on the
home screen". The home screen keeps `layoutRecentActivity` and
`textRecentActivity` only as gone, zero-size placeholders; nothing observes
`AuditLogDao.observeRecent`. Show the newest audit entries in the Audit Log
card, with the same operation labels the audit screen uses.

## Slices (in order)

1. Tests first: `ui/RecentActivityRowsTest` against a stub
   `RecentActivityRows` (returns no rows) and a stub `AuditOperationLabels`,
   so the suite compiles and fails:
   - a row's label is the audit screen's label for its operation type
     (`AuditOperationLabels.labelRes`, e.g. KEY_CREATED ->
     `audit_log_op_key_created`);
   - a success row and a failure row carry different outcomes and outcome
     strings;
   - the relative time comes from an injected `java.time.Clock` (just now,
     minutes, hours, days);
   - at most N rows, newest first, whatever the input order;
   - an empty list gives the single empty-state row;
   - no row carries the details JSON or a raw key id (key label only).
2. The fix: `ui/AuditOperationLabels` (operation type -> string resource,
   lifted from `AuditLogActivity.getOperationTypeDisplayName` and its
   filter-chip list), `ui/RecentActivityRows` (pure, no Android imports
   beyond `R`), `AuditLogActivity` using the shared labels.
3. The home screen: the Audit Log card gains a Recent Activity section
   (`layoutRecentActivity`, a vertical container); `MainActivity` collects
   `AuditLogDao.observeRecent(N)` under `repeatOnLifecycle(STARTED)` and
   renders the rows; tapping the card still opens `AuditLogActivity`. The
   gone placeholders are removed.
4. `docs/audit-log/architecture.md` describes the home-screen view.

## Review fixes

1. Times stopped aging until the audit table changed: `observe` combines
   `observeRecent` with a once-a-minute `ticker`, collected under
   `repeatOnLifecycle(RESUMED)`; tested against a mockk `AuditLogDao`.
2. Rows showed raw key ids: signing, decryption and FIDO2 creation log the
   key id as `keyLabel`. Tests first: `build` given the stored keys'
   labels (key id -> label) shows the stored label, and shows no key text
   when the logged label is a key id with no stored key. Fix: `observe`
   also combines `KeyDao.observeAll()` as that map.
3. No test drove the home screen: `MainActivityRecentActivityTest`
   (Robolectric, `ActivityScenario`) starts `MainActivity` on an in-memory
   `XKeyDatabase` and reads the rows on screen (operation, key label,
   outcome, time), then advances the clock and main looper a minute and
   sees the time re-labelled (Robolectric joins the unit-test bundle).

## Gates

`make test` (ui, audit packages) and `make android-lint`.

## Out of scope

`AuditLogger` (its call sites keep logging ids), `AuditLogDao`, the Room
schema; operation colours on the home screen; new audit event types.
