# #158: the SAS trust-publication test exercises the race

## Objective

`BleClientPhoneInitiatedSasTest.aDisconnectAtTheTrustPublicationTrustsNothing`
drops the link from `sasTrustHook`, which runs before the ownership check, on
the connecting thread. The drop ends the connection before the check reads it,
so the test passes whether or not the check and the trust publication are one
step under `connectionLock` (the guard from #137). The test must drop the link
*while* the trust step runs and fail when the guard is removed.

## Slices, in order

1. This plan.
2. Seam (production, test-only): a hook `sasPublishHook` called inside the
   trust step, under `connectionLock`, once the ownership check has passed
   and before `trusted` is published. Null in production.
3. Test: the hook is the gate. It checks that nothing is trusted yet (the
   connection's `trusted` is false and `sasConfirmed` is not complete), then
   starts the GATT disconnect on another thread and holds the publication
   until that thread has either finished or is blocked on `connectionLock`
   (read through `ThreadMXBean`, so a transient block on another monitor does
   not release the gate). The disconnect thread records the connection's
   `trusted` at the moment it ends the connection (`stateChangeHook`). The
   test asserts that value equals the final one: nothing becomes trusted after
   its connection ended. If the link ended untrusted, `connect()` returns
   false; the disconnect thread finishes and the client ends disconnected.
   - With the guard: the drop waits for the publication, so it ends a trusted
     connection and releases it. Passes.
   - Guard removed (check and publication as two `connectionLock` steps, the
     hook between them): the drop ends the connection in the gap, and the
     publication then trusts it. Fails.
4. Remove `sasTrustHook`, which nothing uses after slice 3.

## Out of scope

- Any change to the trust step's behaviour; the guard stays as it is.
- The other SAS tests in the file.
