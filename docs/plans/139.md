# Plan: send remote.listBackups and remote.syncStatus (#139)

## Objective

The desktop serves `remote.listBackups` and `remote.syncStatus`; the phone
names both in `MethodNames` and never sends them. Send them with the wire
shapes of go-xkms `pkg/pairingproto` at tag `xkey/v0.64.2-alpha`
(`RemoteListBackupsParams`/`Result`, `BackupInfo`,
`RemoteSyncStatusParams`/`Result`), list the desktop's backups before a
restore, and show the desktop's sync status after a sync.

## Slices, in order

1. **Tests for the two client calls** (`RemoteBackupClientTest`,
   `RemoteSyncClientTest`): method name, empty params object (no password),
   parsing of `backups[]` (`backup_id`, `created_at`, `label` omitted when
   empty, `size` int64) and of `last_sync` (omitempty), `device_id`,
   `store_checksums`; error and timeout paths; an unreadable reply.
2. **Client calls**: `RemoteBackupClient.listBackups()` and
   `RemoteSyncClient.syncStatus()`. `listBackups` sends without a password
   field; the password path is unchanged.
3. **Restore flow lists first**: `XKeyGattService.listDesktopBackups()`; the
   restore dialog runs the listing before it asks for the password and says
   whether the desktop holds the chosen backup (`DesktopBackupForm.listing`,
   JVM-tested in `DesktopBackupFormTest`). A listing failure does not block
   the restore: the envelope is the phone's, the desktop only decrypts it.
4. **Sync shows the desktop's status**: `XKeyGattService.syncNow()` asks for
   `remote.syncStatus` after the store legs; the Sync Now result shows the
   desktop's last sync time (`SyncStatusText`, JVM-tested). A status failure
   does not fail the sync.
5. **Docs**: `docs/store-sync/architecture.md` (why `remote.syncAll` is not
   sent), `docs/remote-backup-password/`. `docs/SPEC.md` is unchanged: the
   store-sync row's "outbound through `remote.sync*`" already covers both
   methods, and widening a normative row needs the owner.

## Out of scope

- `remote.syncAll`: not sent. Its params carry only include flags, no phone
  items, so the desktop could not merge the phone's stores; the three
  per-store calls push and pull in one round trip each.
- Restoring a backup by id from the desktop: `remote.restoreBackup` takes
  `backup_data`, not an id, so the listing informs, it does not select.
- Comparing `store_checksums` with the phone's own digests: the two sides'
  digest inputs are not pinned to match.
- Any go-xkms change; any other wire change.
