# 323: OATH list actions

## Objective

The OATH list shows each credential's account name as a small title with its
code underneath. A short tap copies the code; a long press offers Copy,
Delete and Details (plus the desktop entries). Every copy puts the code that
is current when the action runs on the clipboard, marked sensitive, and takes
it off again after 45 seconds only when the clipboard provably still holds it.

## Slices, in order

1. Clipboard ownership. `SensitiveClipboard` clears through one ownership
   check: a readable description with the copy's own token clears; a
   readable foreign token drops the pending clear; an unreadable clipboard
   (Android 10+ without window focus) clears nothing and stays pending until
   any window of the app regains focus (`ClipboardFocusRetry`, one
   app-wide hook registered in `XKeyApplication`, calls
   `retryPendingClears`). The 45 s deadline is on `MonotonicClock.SYSTEM`,
   so time asleep counts.
   Tests: `SensitiveClipboardTest` (Robolectric, injected token reader;
   sleep cases stub only the sleep-inclusive clock),
   `ClipboardFocusRetryTest` (a plain Activity through the hook),
   `OathChokePointsTest.deadlinesUseTheSleepInclusiveClock` and
   `pendingClearsRetryFromOneAppWideHook`.
2. Details survive a failed code. `OathCurrentCode` computes the
   non-advancing TOTP/HOTP code with failure as a value; the list and the
   details screen both use it. The details screen shows the metadata, an
   unavailable code and a disabled Copy.
   Test: `OathCredentialDetailViewModelTest` failure cases.
3. Copy resolves the code when it runs. `OathCodeClipboard.copy(oathId)`
   takes the code from `OathRepository.generateCode` for tap, long-press
   Copy and details Copy; a failure shows one generic message.
   Tests: `OathCodeClipboardTest` (menu open across a period),
   `OathChokePointsTest` (source scan of the three choke points).

## Out of scope

- An instrumented test of another app replacing the clip while xKey is in
  the background: instrumentation runs in the app's own process and uid, so
  it cannot act as another app; the Robolectric reader seam covers it.
- `setPrimaryClip` calls that copy public data (PEMs, fingerprints).
