# 323: OATH list actions

## Objective

The OATH list shows each credential's account name as a small title with its
code underneath. A short tap copies the code; a long press offers Copy,
Delete and Details (plus the desktop entries). Every copy puts the code that
is current when the action runs on the clipboard, marked sensitive, and takes
it off again after 45 seconds only when the clipboard provably still holds it.

## Slices, in order

1. Clipboard ownership. `SensitiveClipboard` clears through one ownership
   check: a readable description with the copy's own token clears; a
   readable foreign token drops the pending clear; an unreadable clipboard
   (Android 10+ without window focus) clears nothing and stays pending until
   any window of the app regains focus (`ClipboardFocusRetry`, one
   app-wide hook registered in `XKeyApplication`, calls
   `retryPendingClears`). The 45 s deadline is on `MonotonicClock.SYSTEM`,
   so time asleep counts; a focus return before the deadline re-arms the
   one timer (`scheduleCheck`) for the time left on that clock.
   Tests: `SensitiveClipboardTest` (Robolectric, injected token reader;
   sleep cases stub only the sleep-inclusive clock; `a focus before the
   time is up after a sleep clears at the time left` and `a re-armed clear
   still leaves a clip that is not ours`),
   `ClipboardFocusRetryTest` (a plain Activity through the hook),
   `OathChokePointsTest.deadlinesUseTheSleepInclusiveClock`,
   `pendingClearsRetryFromOneAppWideHook` and
   `clipboardTimerIsArmedInOnePlace`.
2. Details survive a failed code. `OathCurrentCode` computes the
   non-advancing TOTP/HOTP code with failure as a value; the list and the
   details screen both use it. The details screen shows the metadata, an
   unavailable code and a disabled Copy.
   Test: `OathCredentialDetailViewModelTest` failure cases.
3. Copy resolves the code when it runs. `OathCodeClipboard.copy(oathId)`
   takes the code from `OathRepository.generateCode` for tap, long-press
   Copy and details Copy; a failure shows one generic message.
   Tests: `OathCodeClipboardTest` (menu open across a period),
   `OathChokePointsTest` (source scan of the three choke points).
4. Imports keep computable credentials. `OathRepository.importParsed`
   checks the period only for TOTP, and only that it is positive (the rule
   `OathEngine.generateTotpCode` applies): HOTP ignores the period, and a
   600 s TOTP still computes, so neither aborts a sync batch.
   Test: `OathRepositoryHardeningTest` (HOTP period 0 and TOTP period 600
   through both import paths are stored, the 600 s row yields a code).
5. One scanner client per helper. `QrCodeScannerHelper` takes a
   `scannerFactory`, creates one ML Kit client on its first `start()` and
   keeps it across rejected-code restarts; `stop()` unbinds the frames and
   closes the client once, after any decode in flight calls back.
   Tests: `QrCodeScannerHelperLifecycleTest` (Robolectric, counting
   factory, pending decode across stop), `QrScannerChokePointTest`
   (one `BarcodeScanning.getClient`, outside `bindCamera`; one close).
   The real client is made only for the camera's frames or a given
   factory: making it on `start()` for every source broke
   `QrScannerRejectedCodeTest`, whose fake source decodes on its own,
   because ML Kit is not initialized under Robolectric and the client
   call threw `IllegalStateException` during activity setup.
6. Exhausted HOTP counter. Imports keep a counter at `Long.MAX_VALUE`;
   `claimCounter` claims only below it, so SQLite never stores a REAL.
   `generateCode` throws `OathCounterExhaustedException` for it, and a
   failed claim that did not move the counter ends in an error, not a loop.
   `OathCurrentCode` shows no code for it. Tests: `OathRepositoryHardeningTest`
   (both imports at MAX, MAX - 1 then MAX, list shows no code, a claim that
   never succeeds), `OathChokePointsTest` (one guarded `counter + 1`).

## Out of scope

- An instrumented test of another app replacing the clip while xKey is in
  the background: instrumentation runs in the app's own process and uid, so
  it cannot act as another app; the Robolectric reader seam covers it.
- `setPrimaryClip` calls that copy public data (PEMs, fingerprints).
