# 341: passkey provider entry-point tests

## Objective

The system credential manager reaches the passkey provider through
`XKeyCredentialService`, which hands out pending intents from
`CredentialPendingIntentHelper` that start `CredentialSelectorActivity`.
The handlers behind them are well tested; the entry points are not. This
row adds tests for the entry points and fixes, test first, any bug they
find in the four entry-point files.

## Slices, in order

1. `XKeyCredentialServiceTest` (Robolectric, `Robolectric.buildService`,
   handlers and the settings repository replaced with `mockkConstructor`):
   switch off, begin-create and begin-get answer empty responses and no
   handler is called; switch on, they answer the handler's entries; a
   throwing handler reaches `onError` with the unknown exception of its
   family and never `onResult`; a handler's `CancellationException` still
   answers exactly once; clear-state answers `onResult(null)` and calls no
   handler.
2. `CredentialPendingIntentHelperTest` (Robolectric): each pending intent
   is an activity intent for `CredentialSelectorActivity` with the
   action and extras the selector reads and a prompt key, is mutable
   (the framework fills in the request), and successive intents carry
   distinct request codes, so one never replaces another's extras.
3. `CredentialProviderSettingsUnitTest` (Robolectric): feature
   availability by API level, the default before any write, the on/off
   round trip and the settings flow, `clearSettings`,
   `openSystemCredentialSettings` (first intent, fallback, false when
   nothing resolves) and the enable gate reading the stored switch on
   every request.
4. `CredentialSelectorErrorPathTest` (device): a get with no extras, a
   garbled request JSON, an unknown credential id, and a create with
   garbled JSON each return `RESULT_CANCELED` with an exception of their
   family and leave the credential table as it was; a user verification
   the user cancels returns an error and stores no credential.
5. Any bug: a failing-test commit, then a fix commit in one of the four
   entry-point files.

## Out of scope

- `CreateCredentialHandler` and `GetCredentialHandler` (an open pull
  request changes both): a bug there goes in the report.
- New test dependencies.
