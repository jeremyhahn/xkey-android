# #213: the CRL lists only what its issuer signed; a revocation is final

## Objective

`AndroidCA.generateCRL()` signs with the current intermediate but lists every
revoked row in `certificates`, whatever signed it: the intermediate's own row
(issued by the root), and after `reset()` and a fresh initialise, every serial
the old intermediate signed under the same name. RFC 5280 section 5.1: a CRL
that is not indirect lists only certificates its issuer signed. And a second
revocation of a serial overwrites the first date and reason and logs again.

## The issuer check

A revoked row goes on the CRL only when its stored certificate
(`certificatePEM`) parses and was issued by the current intermediate:

1. the certificate's issuer name equals the intermediate's subject name
   (DER compare of the X500Principals), and
2. the certificate's signature verifies with the intermediate's public key.

(2) separates two intermediates with the same name, as after `reset()`; the
authority key identifier is not used because a certificate may omit it, while
the signature is always there. A row whose PEM does not parse is left out and
logged: the CRL cannot claim a certificate it cannot show its issuer signed.

The check is an `internal` pure function in `AndroidCA.kt`
(`revokedIssuedBy(rows, issuer)`), so a test needs no Keystore.

## The revoke guard

`CertificateDao.revoke` updates only `WHERE serial_number = :serial AND
revoked = 0` and returns the rows changed. `AndroidCA.revoke` returns `true`
when it revoked the certificate, `false` when it was already revoked: no second
audit entry, the first `revokedAt` and reason stay. The management screens call
the DAO, so they get the same rule without an edit.

## Slices, in order

1. This plan.
2. Failing tests, `app/src/test/kotlin/com/automatethethings/xkey/ca/AndroidCARevocationTest.kt`
   (JVM, in-memory KeyStore and mocked DAO as in `AndroidCAIssuanceValidityTest`):
   - the CRL lists a revoked leaf the current intermediate signed;
   - it leaves out the intermediate's own revoked row (issued by the root);
   - it leaves out a revoked row signed by a different key under the same
     issuer name (the old intermediate after `reset()`);
   - revoking an already revoked serial writes no audit entry and returns false;
   - the first revocation returns true and logs once.
3. The fix: `revokedIssuedBy`, `generateCRL`, `AndroidCA.revoke`,
   `CertificateDao.revoke`; a "Revocation" section in
   `docs/certificate-authority/engineering.md`.

The DAO's `revoked = 0` guard is SQL that only Room runs (an instrumented
`CertificateDaoTest` case is outside this lane's file map: a follow-up); the
JVM test checks that `AndroidCA.revoke` honours the DAO's answer.
