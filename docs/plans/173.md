# #173: local.pivImportCert refuses a certificate for another key

## Objective

`PivKeyManager.importCertificate` stored `certificate_der` unparsed once the
slot row existed. It now parses the bytes as one X.509 DER certificate and
stores it only when the certificate's SubjectPublicKeyInfo equals the slot
key's public key. `local.pivImportCert` maps the refusals onto existing
codes; the success result is unchanged.

| Request | Result |
|---------|--------|
| Certificate for the slot's key | stored, `success: true` |
| Certificate for another key | `INVALID_PARAMS`, earlier certificate kept |
| Bytes that are not one DER certificate | `INVALID_PARAMS`, nothing stored |
| `certificate_der` not base64 | `INVALID_PARAMS`, nothing stored |
| Slot with no key | `PIV_SLOT_NOT_FOUND` (-32026) |

## Slices, in order

1. This plan.
2. Failing tests (one commit):
   - `PivKeyManagerTest`: matching certificate stored; certificate for
     another key refused with no upsert; non-certificate bytes refused; no
     slot row refused. Certificates are built in the test with Bouncy
     Castle for a JDK-generated P-256 key standing in for the slot key.
   - `PivHandlerTest`: the same cases through `RequestHandler` over a real
     `PivKeyManager` and a mocked `PivSlotDao`, asserting the wire code,
     plus bad base64.
3. Fix: typed exceptions in `PivKeyManager.kt`
   (`PivCertificateRejectedException` with not-a-certificate and
   key-mismatch subclasses, `PivSlotEmptyException`); the Keystore is opened
   lazily so the import path runs in JVM tests; the handler maps them.
4. Docs: `docs/piv/architecture.md` wire row and errors table.

## Out of scope

- Certificate chain, validity period or signature checks.
- Other PIV handlers and their error codes.
- New error codes.
