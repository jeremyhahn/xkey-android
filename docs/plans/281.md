# Plan: fido2-phone-backend, CTAP2 over BLE (#281)

## Objective

The SPEC row fido2-phone-backend requires CTAP2 over BLE so that
`xkey fido2 --backend phone` authenticates with keys on the phone after a
biometric prompt there. The phone does not speak CTAP2 yet: it serves
`local.listFido2Credentials` and `local.signFido2Assertion` over the paired
Noise session (BLE, TCP or USB). The requirement stays on the row, marked not
yet shipped, until the CTAP2 slice lands.

## Slices

1. Docs (this slice). SPEC.md row status "in progress"; the Requirements cell
   keeps its requirement text verbatim and adds what ships today and
   "CTAP2 over BLE: not yet shipped (#281)". ROADMAP.md moves the row from
   Complete to Now with #281. `docs/fido2-phone-backend/architecture.md`
   says CTAP2 over BLE is not yet shipped. No code, no tests.
2. CTAP2 over BLE (later slice on #281). The implementation and its unit and
   integration tests are planned in that slice, which updates this file.
