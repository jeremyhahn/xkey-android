# 125: the bridge-stage module proxy list ends without `direct`

Problem: `scripts/in-toolchain-image.sh` gave a bridge-network stage a module
proxy list of `https://proxy.golang.org` then `direct`, so a module the proxy
cannot serve was fetched from its origin repository instead of failing the stage.

Change: the stage's GOPROXY is `https://proxy.golang.org` alone, and the script's
comments say the stage takes modules from the proxy only. GOMODCACHE, GOPRIVATE
and the credential pass-through are unchanged.

Acceptance: no GOPROXY value in the tree ends in `direct` (a git grep for an
assignment followed by `direct` on the same line finds nothing); `bash -n` and `shellcheck` on the
script pass; `make lint-gates` passes.
