# 342: direct tests for CTAP2 request parsing, the CBOR decoder and BLE lifecycle generations

## Objective

Every CTAP2 request a nearby device sends over BLE is decoded by
`CborDecoder` and validated by `Ctap2Requests` before any key is touched, so
both face untrusted input. Neither had a test calling it directly, and
`LifecycleGeneration`, the guard each BLE start checks before it publishes a
server or advertiser, had no test. This row adds plain JVM tests for all
three and one end-to-end JVM test of malformed messages through the BLE
session.

## Slices, in order

1. `Ctap2RequestsTest`: one test per refusal of `Ctap2Requests.makeCredential`
   and `getAssertion` (short request, invalid CBOR, non-map top level, each
   required field missing, each field of the wrong type, clientDataHash
   length, pubKeyCredParams entries, excludeList and allowList descriptors,
   options, pinUvAuthParam, extensions, lengths), then the accepted shapes
   (minimal, every optional field, unknown keys ignored).
2. `CborDecoderBoundsTest`: trailing bytes, truncation in a header and in
   byte and text strings, declared lengths beyond the input (including array
   headers of 2^31 and 2^63 items), MAX_DEPTH accepted and MAX_DEPTH + 1
   refused, integers above 63 bits, indefinite lengths, tags, floats and
   simple values, invalid UTF-8, non-scalar map keys, duplicate keys and
   negative-integer edges. Every refusal is a `CborDecodingException`.
3. `LifecycleGenerationTest`: begin, advance, end, isCurrent and publish,
   and an advance or end racing a publish waits for the block.
4. `Ctap2MalformedMessageTest`: fragmented MSG frames carrying truncated
   CBOR, an oversized declared array, deep nesting and a duplicate key
   through a `FidoBleSession` wired to a real `Ctap2Authenticator`; each
   answers one CTAP2 status, the session serves the next valid request and
   the backend is never called.
5. A bug found: a commit with only the failing test, then the fix in
   `Ctap2Requests.kt`, `CborEncoder.kt` (the decoder) or
   `LifecycleGeneration.kt`.

## Out of scope

- Behaviour changes beyond a test-first fix for a bug found here.
- `AndroidFidoCredentialBackend.kt`, `PendingKeyDeletions.kt` and
  `XKeyGattService.kt`: an open pull request changes them; a bug there is
  reported, not fixed.
- Device (instrumented) tests: these classes are pure JVM.
- New test dependencies.
