## Objective

Correct `docs/SPEC.md` wording only where the correction changes no
requirement. A requirement leaves SPEC.md only by the owner's own edit, so
this PR narrows no row and removes no code.

## What this PR keeps

Nothing in `docs/SPEC.md`: after review every proposed rewrite either
narrowed a requirement or dropped one, so all three rows are byte-identical
to main.

- **device-attestation.** The rewrite named the shipped classes
  (`DeviceAttestationKey`, `AttestTranscript`, `AttestedKeyFingerprint`) but
  no longer stated that the Device Attestation Key is attested to an Android
  hardware root. That is a requirement, so the row is restored as main has
  it. One correction that changes no requirement remains open: main's row
  names a `DeviceFingerprint` type, and the code's type is
  `AttestedKeyFingerprint`. It is left for the owner rather than reworded
  here.

  certificates" in favour of `verifyIDevIDChain` alone and deleted
  `IDevIDVerifier` (with its test and its lines in the trust-store and
  hardware-backed-keys architecture pages). The IDevID wiring is now
  **#280**, with its own PR; `IDevIDVerifier.kt`, `IDevIDVerifierTest.kt`
  and both architecture pages are as on main.
- **fido2-phone-backend.** Restored. The rewrite replaced "CTAP2 over BLE"
  with the JSON-RPC methods the phone serves over BLE, TCP and USB, which
  drops the CTAP2-over-BLE requirement. CTAP2 over BLE is now **#281**, with
  its own PR.

The clause-by-clause shipped-behaviour table the earlier lanes wrote (owner
ruling 632) is in this branch's history; it is the evidence #280 and #281
start from.
