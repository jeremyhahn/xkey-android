# Plan: SPEC rows the code contradicts (#136)

## Objective

Set the wording of three `docs/SPEC.md` rows to what the code on main does,
naming only classes, paths and methods that exist. No row's Status changes.

## Slices, in order

1. **trust-store-bootstrap row.** The row says the app "verifies IDevID
   certificates". On main the only chain check with a caller is
   `TrustStoreRepository.verifyIDevIDChain`, used by `GattServer` on the TPM
   endorsement key certificate during enrollment. `IDevIDVerifier` has no
   caller outside its test and checks nothing `verifyIDevIDChain` does not
   (self-signed leaf, PKIX path to a stored CA; expiry is part of PKIX). Its
   extras are result shaping (subject, fingerprint, `notAfter`) and
   `isIDevIDStillValid`, which nothing calls. Remove `IDevIDVerifier.kt` and
   `IDevIDVerifierTest.kt`, and its lines in the trust-store architecture
   page. Test: `make test` passes with the class gone.
2. **device-attestation row.** The phone does not attest the key to a root:
   it mints the DAK once under `AttestTranscript.GENESIS_CHALLENGE` and
   returns the Keystore chain, which the desktop checks. There is no
   `DeviceFingerprint` type; the fingerprint is `AttestedKeyFingerprint`,
   stored as the paired device's `deviceFingerprint`. Reword to
   `local.attestDevice` protocol version 2 as built.
3. **fido2-phone-backend row.** The phone does not speak CTAP2 and the
   methods are not BLE-only: it serves `local.listFido2Credentials` and
   `local.signFido2Assertion` over the paired Noise session on BLE, TCP and
   USB; the prompt is raised only when the request requires UV and the
   session needs a fresh biometric. Reword to that.

No tests are added: slices 2 and 3 are wording only, slice 1 removes dead
code and its test.
