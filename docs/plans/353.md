# 353: tests for the desktop keys screen

## Objective

`DesktopKeysController` has JVM tests; `DesktopKeysActivity`, which binds
`XKeyGattService`, adapts the session's `RemoteKeyClient`, renders each
`DesktopKeysState` and wires the taps, back and Snackbar retry, has none.
Cover the activity with Robolectric tests (plain `Application`, SDK 34,
mockk for the service and the client) and fix what they find, each fix
after a commit holding only its failing test.

## Slices

1. `DesktopKeysTestService` (test helper) and `DesktopKeysActivityUiTest`:
   - backend rows: name, type, hardware or software; empty-list text;
   - a backend tap sends `listKeys(name)` and shows its keys (label, or the
     key id when the label is empty); empty-list text;
   - a key tap sends `getKeyInfo` and `getPublicKey` and shows the detail
     fields, the public key or the unavailable reason; createdAt of zero or
     below shows the raw number;
   - sign test and attest buttons only when the backend supports them;
     sign test shows valid or invalid with the algorithm; attest shows
     format, certificate count, data bytes and nonce;
   - both buttons disabled while a step loads;
   - each `DesktopKeyError.Kind` shows its own text.
2. `DesktopKeysActivityLifecycleTest`:
   - no peer extra, another desktop's session, an unconfirmed session
     (the service reports none) and no session: no-session text, nothing sent;
   - one adapted source per client across steps; a new client after a
     reconnect is refused (no-session text, nothing sent on it);
   - a second `onServiceConnected` with the same session;
   - a refused bind leaves Loading;
   - back walks detail, keys, backends, then finishes; back cancels a step
     in flight;
   - a failure's Snackbar retry repeats the failed step; after a back the
     retry does not reopen the screen the user left;
   - `onDestroy` unbinds once; a recreated activity opens again.
