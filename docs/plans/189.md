# Plan 189: audit trust store imports and deletes

## Objective

`AuditLogger.logTrustStoreImport` and `logTrustStoreDelete` have no caller, so
adding or removing a trusted CA never reaches the audit log. Record both from
`TrustStoreRepository`, which every trust store write goes through (manual
import, URL import, bootstrap, trust store sync, internal CA).

## Slices

1. Failing tests (`TrustStoreRepositoryTest`), capturing entries through
   `AuditLogger`'s `daoRef`/`scopeRef` holders (relaxed DAO mock,
   `Dispatchers.Unconfined`, both reset in `@After`):
   - importCertificate records one TRUST_STORE_IMPORT with subject,
     fingerprint and source `manual`;
   - a duplicate import and a self-signed certificate record nothing;
   - importFromURL records one import per stored certificate with source
     `url:<url>`;
   - importInternalCACertificate records source `internal-ca`;
   - deleteCertificate of a stored certificate records one
     TRUST_STORE_DELETE; of an unknown fingerprint, nothing;
   - clearAll over two certificates records two deletes.
2. Fix in `TrustStoreRepository`:
   - `storeCertificate` logs the import after the DER and metadata are
     written, with the subject, the repository's fingerprint and `source`;
   - `deleteCertificate` logs only when it returns true, with the subject from
     the metadata row (empty when only the file existed);
   - `clearAll` reads the metadata first and logs one delete per entry.
   - The repository logs only when `AuditLogger.isInitialized()`: the
     uninitialized drop path calls `android.util.Log.w`, which throws in JVM
     unit tests (no `returnDefaultValues`), so callers that never initialize
     the logger (e.g. `TrustStorePersistenceTest`, sync) would break.
3. `docs/audit-log/architecture.md` names the trust store events.

## Out of scope

- Any change to `AuditLogger` or its signatures.
- `AuditLoggerDispatchTest`, the UI activities and `sync/`.
- Auditing refused or failed imports.
