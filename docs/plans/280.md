# #280: TPM enrollment verifies the EK certificate through IDevIDVerifier

## Objective

The trust-store-bootstrap SPEC row says the app verifies IDevID certificates.
`IDevIDVerifier` exists but nothing in `app/src/main` calls it: TPM
enrollment (`GattServer.verifyEndorsementKey`) calls
`TrustStoreRepository.verifyIDevIDChain` itself, and in doing so

- accepts an EK certificate when the trust store holds no anchors
  (`NoTrustAnchors`), with only a warning;
- accepts an EK certificate unchecked when no trust store is wired;
- lets an exception from the chain check escape as something other than an
  enrollment refusal, so nothing is audited.

After this row there is one choke point: `GattServer` holds an injected
`IDevIDVerifier`, `verifyEndorsementKey` calls `IDevIDVerifier.verify` once,
and only `Trusted` lets enrollment continue. `SelfSigned`, `Untrusted`,
`NoCertificate`, `Error`, and a missing verifier each refuse with
`EnrollmentRefusal.UntrustedEndorsement` and a reason (never certificate
bytes).

## Slices (in order)

1. Plan (this file).
2. Test only: `app/src/test/.../ble/GattServerEndorsementVerifierTest.kt`
   drives the private `verifyEndorsementKey` by reflection with a parsed
   TCG-CSR-IDEVID carrying a CA-issued EK certificate:
   - trust store reports `NoTrustAnchors` -> refused (fails on base);
   - trust store throws -> refused with a refusal, not the raw exception
     (fails on base);
   - no trust store / verifier wired -> refused (fails on base);
   - trust store reports `Invalid` -> refused;
   - trust store reports `Valid` -> the EK certificate is returned.
3. Fix: `GattServer` takes `idevidVerifier: IDevIDVerifier?` (defaulting to
   one built over `trustStoreRepository`, so existing wiring keeps
   compiling); `XKeyGattService` passes it explicitly;
   `verifyEndorsementKey` routes through it; sweep `app/src/main` for any
   other direct `verifyIDevIDChain` caller on an IDevID/EK path;
   `docs/trust-store-bootstrap/architecture.md` names the caller.

## Out of scope

- Changing `TrustStoreRepository.verifyIDevIDChain` or the
  `IDevIDVerificationResult` shape.
- Bundling TPM vendor roots so a fresh store has anchors; a store with no
  anchors now refuses TPM enrollment until roots are imported.
- `IDevIDVerifier.isIDevIDStillValid` callers (re-verification of stored
  EK certificates).
- Instrumented (`androidTest`) enrollment suites: they never reach the EK
  step (no Noise session), so they are unchanged.
