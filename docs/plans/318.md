# 318: PIN lockout and audit row, unit tests green

## Objective

The row branch moved the vault lockout onto an injected monotonic clock,
moved OATH audit rows into `OathRepository`, and records every policy
refusal once in the dispatcher. Five JVM unit tests fail at the branch
head; this slice makes them pass without weakening any assertion.

## Slices, in order

1. Test: `PolicyDeniedAuditTest` gains a case where a refusal on a served
   connection that authenticated no peer writes no POLICY_DENIED row.
2. Fix: `RequestHandler.auditPolicyDenied` takes its peer as
   `val callerPeer = currentPeerPublicKeyHex()` (the source guard's
   naming) and writes no row when the request carries a `CallerSession`
   but no peer. In-process requests record as before; the response never
   changes. Pinned by the new case and by
   `KeyShareAuditTest.aConnectionWithNoPeerKeyIsRefusedAsAnonymous` and
   `noAuditPathReadsTheHandlerWidePeer` (unchanged).
3. Test setup: `SyncEngineMergeOathTest` stubs `AuditLogger` and verifies
   the created row a synced add now writes; `PasswordStoreMethodsTest`,
   `UsbWireContractTest` and `PasswordSyncTest` pass the shared
   `FakeLockoutClock` to `PasswordVault`, so no JVM test reads
   `SystemClock`.

## Out of scope

- The vault's behaviour when recording a failure throws (a device clock
  cannot).
- The dispatcher's catch structure, docs.
