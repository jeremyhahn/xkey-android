# 318: PIN lockout and audit row, unit tests green

## Objective

The row branch moved the vault lockout onto an injected monotonic clock,
moved OATH audit rows into `OathRepository`, and records every policy
refusal once in the dispatcher. Five JVM unit tests fail at the branch
head; this slice makes them pass without weakening any assertion. A second
slice keeps secret dialogs off screen capture and closes three audit gaps.

## Slices, in order

1. Test: `PolicyDeniedAuditTest` gains a case where a refusal on a served
   connection that authenticated no peer writes no POLICY_DENIED row.
2. Fix: `RequestHandler.auditPolicyDenied` takes its peer as
   `val callerPeer = currentPeerPublicKeyHex()` and writes no row when the
   request carries a `CallerSession` but no peer.
3. Test setup: `SyncEngineMergeOathTest`, `PasswordStoreMethodsTest`,
   `UsbWireContractTest` and `PasswordSyncTest` stub what the branch reads.
4. Secret dialogs: every dialog in a UI file with a password-type input,
   and the OATH secret entry, is shown through `SecureScreens.show`.
   Tests: one FLAG_SECURE case per PIN dialog in
   `PinManagementActivitySecureTest`; `SecureDialogSourceGuardTest`
   counts builders against `SecureScreens.show` calls per guarded file.
5. Audit deletion: clear and delete-older run as one Room transaction with
   their AUDIT_LOG_CLEARED / AUDIT_LOG_PRUNED row
   (`AuditLogDao.deleteAllAndRecord` / `deleteOlderThanAndRecord` behind
   `AuditLogger.clearAuditLog` / `pruneAuditLog`). Tests: commit and
   rollback cases in `AuditLogDaoTest`; `AuditDeletionChokePointTest`
   source guard.
6. Returned denials: `dispatch` audits OPERATION_DENIED from the response
   it returns, so thrown and returned refusals write one row each. Tests:
   cosign and import refusals in `PolicyDeniedAuditTest`.

## Out of scope

- The vault's behaviour when recording a failure throws (a device clock
  cannot).
- The dispatcher's other catch blocks, docs.
- FLAG_SECURE on screens that take no secret; the automatic retention
  prune.
- Copying an OATH code on the phone: the open OATH list change copies
  through the audited `OathRepository.generateCode`.
