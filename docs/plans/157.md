# #157: the revocation test waits on signals, not sleeps

## Objective

`TcpHsmServerRevocationTest` must not use `delay()` as synchronisation.
Each wait is on a signal the server or the test raises, so each test
proves the revocation path ran.

## Finding

Main already meets the objective. #100 replaced the `delay(200)` after
the approval and the two `delay(500)` calls in the blocked-write helper
with signals:

- approval test: `started` (the handler is running), then `finished`
  (the handler body ended), and `ran` stays false;
- blocked-write helper: `HoldingOutputStream.writeBlocked` (a write that
  cannot finish has started) and, for the queued answer,
  `TcpHsmServer.beforeSendLockForTest` (the answer waits on the send
  lock);
- teardown: `server.state` back to `Listening` and
  `verify(timeout)` on `setConnectedDevicePublicKeyHex(null)`.

No `delay()` or `Thread.sleep` is left in the file, and the seams it
needs (`outputStreamForTest`, `beforeSendLockForTest`) are already in
`TcpHsmServer.kt`.

1. This plan (the only commit; no code change is needed).
2. Stability check: the test class run 20 times in a row
