# Plan: maintenance row #317

## Objective

Main is red: every CI image build (Integration and Devcontainer) fails in the
warm Gradle run because Maven Central answers HTTP 429 Too Many Requests for
a Robolectric android-all-instrumented jar, and gradle-retry's three attempts
(15 s, then 30 s apart) end inside the rate limit. The code is not at fault.
Make the image build survive a Maven Central rate limit.

## Slices, in order

1. `ci: retry the image dependency download on HTTP 429 with a longer backoff`
   - build/docker/devcontainer/Dockerfile, gradle-retry: attempts from
     `GRADLE_RETRY_ATTEMPTS` (default 5), delay from `GRADLE_RETRY_DELAY`
     (default 30 s) doubling each time (30, 60, 120, 240), and a 429 /
     Too Many Requests log retried like a failed download.
   - scripts/gradle-retry-test.sh, new cases: a 429 log with no "Could not"
     line is retried; `GRADLE_RETRY_ATTEMPTS` is honoured (fewer and more
     attempts than the default); the default backoff is 30, 60, 120, 240 s
     (sleep stubbed); a failing test whose output names 429 still exits at
     once. New mutant: the 429 alternative removed is caught. Existing
     cases and mutants kept, the bound now the default 5.
2. `build: resolve Maven Central through Google's mirror first`
   - settings.gradle.kts: in both repository blocks, Google's mirror of
     Maven Central between `google()` and `mavenCentral()`, unfiltered.
     Gradle moves to the next repository on a 404 but fails on a 429, so the
     mirror goes first and Maven Central stays as the fallback.

3. `test: device settings restore keeps the saved value on a failed write`,
   then `fix: test runner verifies each settings restore before dropping the
   saved value`
   - androidTest DeviceSettings.kt: the one choke point for shell
     `settings get/put/delete`; empty `get` output is a read failure, every
     write is read back. SettingsGuard (prepare/restore) moves out of
     XKeyTestRunner; a saved original is deleted only after its restore
     reads back, and nothing is written after a failed read.
   - DeviceSettingsTest (fake shell): ignored restore put/delete keeps the
     saved key; failed reads and a failed backup write change nothing.
   - WebAuthnE2ETest.registerAsCredentialProvider goes through the same
     choke point.

## Tests

`make gradle-retry-test` (part of `make lint-gates`). The mirror is proved by

## Slice: CI overflows to self-hosted runners when hosted runners are busy

Objective: when every GitHub-hosted runner slot this repository may use is
taken, a CI run goes to the self-hosted bigdisk pool instead of queueing.

1. `ci: pick the less used runner pool in preflight`
   - .github/workflows/ci.yml preflight: the GitHub-hosted-only runner step
     becomes `Balanced runner pool (ruling 1137)` from the shared template
     (v1.59, a short API listing counted as a lower bound). It counts this
     repository's queued and in-progress jobs per pool and outputs `runner`
     and `runner_docker` for the pool less used. preflight gets
     `actions: read`. preflight's own runs-on stays ubuntu-latest unless
     `CI_PREFLIGHT_RUNS_ON` is set.
   - A pull request whose head repository is not this one (a fork, or a
     deleted fork) gets ubuntu-latest everywhere, before any API call.
2. `ci(code-review): route the bigdisk-eligible jobs the same way`
   - code-review.yml: the jobs the template sends to bigdisk for a
     same-repository head go there only when `CI_SELF_HOSTED_BIGDISK` > 0;
     the `codex` and `qwen` review jobs are unchanged.
   - .github/actionlint.yaml declares the bigdisk labels.

Checks: actionlint when present, every workflow parses as YAML, and no
runs-on names a self-hosted label without the fork guard.

### Switching it on

Nothing leaves GitHub-hosted runners until all of these hold:
- bigdisk and bigdisk-docker self-hosted runners are registered for this
  repository (labels `self-hosted, linux, x64, bigdisk` and
  `self-hosted, linux, x64, bigdisk-docker`);
- the repository variables `CI_SELF_HOSTED_BIGDISK` and
  `CI_SELF_HOSTED_BIGDISK_DOCKER` are set to the job limit of each pool
  (whole numbers above 0; unset or 0 means every job stays hosted);
- `CI_HOSTED_SHARE` is set to this repository's hosted job share
  (unset means 12).
`CI_PREFLIGHT_RUNS_ON` (runs-on JSON) optionally moves preflight itself.

Out of scope: the template's LAN address masking step (internal registry),
scans.yml and signatures.yml.
