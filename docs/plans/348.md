# 348: bootstrap trust over real TLS and Noise

## Objective

CA bootstrap decides which certificate authority the phone trusts. The
existing bootstrap suites never complete a TLS handshake: the HTTPS legs run
through an OkHttp interceptor, so the SPKI trust manager, `computeSPKIPin` and
the DANE client's trust manager have never run, and the Noise path has only
met an honest responder. This row drives each of them against a real loopback
peer and fixes what the tests expose.

## Slices, in order

1. `TlsBootstrapServer` (test helper): a loopback `SSLServerSocket` serving a
   configurable chain and key through an in-memory key manager, answering
   `GET /v1/ca/bootstrap`. `BootstrapSpkiTlsTest`: pinned leaf accepted,
   pinned CA with a leaf it signed accepted, wrong leaf refused with both
   pins, uppercase pin, hostname mismatch refused, HTTP 500 and the 1 MB cap
   over TLS, and an attacker leaf followed by the genuine pinned certificate
   refused.
2. `BootstrapDaneTlsTest`: `DnsStubServer` answers the TLSA query with the AD
   bit, the TLS server presents the chain. DANE-EE match and mismatch (no
   HTTP request), DANE-TA accepted, DANE-TA name mismatch, appended anchor
   the leaf does not chain to, PKIX-only usages, unsigned answer opens no
   TLS connection.
3. `BootstrapNoiseTamperTest`: hostile responders written in the test (wrong
   static key, flipped ephemeral bit, flipped handshake tag, flipped
   response ciphertext, replayed msg2 ciphertext, truncated 65535-byte
   frame, non-JSON reply). Each fails with no bundle; `fetchCABundle` with
   Noise then Direct records the Noise failure and falls through.
4. Each bug: a commit with only the failing test, then the fix commit.

## Findings

- SPKI: the trust manager accepts a chain when any certificate in it matches
  the pin, without checking that the leaf chains to it. A server holding only
  its own key can present its self-signed leaf followed by the public pinned
  certificate (confirmed with a JSSE handshake on JDK 21). Fix: accept a pin
  on `chain[i]` only when every signature from the leaf up to `chain[i]`
  verifies.
- SPKI: JSSE wraps the trust manager's `SPKIException` in an `SSLException`,
  so the `catch (e: SPKIException)` branch never runs and a pin mismatch is
  reported as `DirectException`. Fix: unwrap the cause chain.
- Noise: AEAD, EOF and JSON failures escape `fetchWithMethod(NOISE)` raw
  (`AEADBadTagException`, `EOFException`, `JSONException`) instead of as
  `NoiseBootstrapException`. Fix: wrap them.

## Out of scope

- `BootstrapSettings.kt`, `TrustStoreRepository.kt`, Gradle runs (the lane
  has no Android SDK; compilation is checked by reading).
- The client accepts a msg2 with no AEAD payload (the existing honest test
  responder sends none); not changed here.
