# #242 ui: the PIV and settings screen tests wait on signals, not settle sleeps

## Objective

Remove every fixed `Thread.sleep(SETTLE_MS)` from `PivActivityUiTest` and
`SettingsPersistenceAndDisclosureFlowTest` (instrumented UI tests). A positive
wait polls the observable result with the existing `awaitCondition` /
`awaitActivity` helpers; a "nothing happened" assertion waits for a signal that
the work it guards has finished, never a fixed delay. Follows #171/#172.

## Slices (in order)

1. Plan (this file).
2. `PivActivityUiTest`:
   - `generateKeyDialog_honoursASelectedNonDefaultAlgorithm`: poll
     `dao.getBySlotId(slot.hexId)` until it returns the stored key, then
     assert its algorithm (same assertion as before).
   - `generateKeyDialog_opensForTheSelectedSlotAndCancelsWithoutGeneratingAKey`:
     the "no key" assertion waits for a signal that the dialog's work has
     settled (a test-visible seam in `PivActivity` if needed, no behaviour
     change), then asserts no key was written.
   - drop the `SETTLE_MS` constant.
3. `SettingsPersistenceAndDisclosureFlowTest`:
   - `followingAnExternalChange_doesNotWriteItBack`: wait for a signal that
     the activity's external-change handling has finished (seam or an action
     ordered after it), then assert nothing was written back.
   - drop the `SETTLE_MS` constant.

Tests: the three tests keep their assertions; gates are
`./gradlew compileDebugAndroidTestKotlin testDebugUnitTest` and lint/ktlint.
The lane has no device: CI runs the instrumented classes.

## Out of scope

- Other test classes' sleeps, `piv/`, `auth/`, `usb/UsbHsmSettings.kt`,
  `media/` tests, `e2e/WebAuthnE2ETest.kt`, `res/values/strings.xml`.
- Any behaviour change in `PivActivity` or `SettingsActivity`.
