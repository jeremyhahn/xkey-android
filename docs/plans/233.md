# #233: audit password adds and deletes made on the phone

## Objective

Adding or deleting a password in PasswordManagementActivity writes no
audit entry, while contact and OATH edits do. After this row each add
writes one PASSWORD_CREATED entry and each delete one PASSWORD_DELETED
entry, carrying only the entry id and its display name: never the
password, username, URL or notes.

## Slices, in order

1. Plan (this file).
2. Failing JVM tests:
   - AuditLoggerDispatchTest: `logPasswordCreated` and
     `logPasswordDeleted` record the type, id and name, and no other
     field of the entry.
   - password/PasswordEditsTest (real PasswordRepository over a mocked
     DAO and stub cipher, AuditLogger over a capturing DAO):
     one PASSWORD_CREATED per add with id and name; one PASSWORD_DELETED
     per delete; no entry when the add is refused with
     PasswordEntryTooLargeException, which still reaches the caller; no
     entry for a delete that removed nothing; no entry details or label
     hold the password, username, URL or notes.
3. Fix: two AuditOperationType values appended (stored by name, so no
   Room migration), two AuditLogger helpers, audit screen labels and
   strings, `password/PasswordEdits` (add, delete) calling
   PasswordRepository then the helpers; PasswordManagementActivity calls
   PasswordEdits for add and delete.
4. docs/password-vault/architecture.md states what is audited.
5. Finish: merge main (backup audit types land beside the password
   ones); the test's sample password is built at run time so the
   secret scanner sees no credential-shaped literal.
6. Review fix: PasswordEdits runs each write and its audit through one
   helper under NonCancellable, so a cancellation after the commit cannot
   skip the audit. Tests first: add and delete cancelled after the DAO
   commits are still audited; PasswordEdits' public writes are pinned;
   no main source outside PasswordEdits, the repository, sync and the
   USB verbs writes through the repository.

## Out of scope

- Logging from PasswordRepository itself: the desktop sync path
  (sync/SyncEngine.kt) writes through it and is audited by a separate
  change.
- password/PasswordVault.kt and the USB/BLE password verbs.
- Password edits (there is no edit flow on the phone screen yet).
