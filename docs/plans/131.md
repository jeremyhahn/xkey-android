# 131: as-built feature docs for the transports and the pairing contract

Problem: `docs/SPEC.md` lists shipped features whose Detail cell is `none`, so a
reader who wants the implementation of usb-transport, tcp-pairing,
device-attestation, phone-initiated-pairing or request-generation-echo has to
read all the code to find it. Thirteen more rows (exportable-symmetric-keys,
pin, piv, oath, protected-memory, fido2-phone-backend, fido2-built-in-uv,
release-signing, store-sync, desktop-backup-store, trust-store-bootstrap,
password-vault, remote-backup-password) are in the same state and get their
docs from parallel lanes.

Change: one `docs/<feature>/architecture.md` per feature above (Summary,
Components with file paths, wire methods or Android entry points, one mermaid
sequence diagram of the main flow, errors and refusals, tests, related
features), each describing only what the code on main does. The Detail cell of
the 18 SPEC rows becomes `docs/<feature>/`; no other SPEC text changes.

Acceptance: each of the five features has `docs/<feature>/architecture.md`;
every class, file, method and wire-method name a page cites is found by a
`git grep` on main; `make lint-gates` passes; no file outside the lane's file
map changes.
