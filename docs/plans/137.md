# Plan: confirm the SAS on phone-initiated sessions (#137)

## Objective

Sessions the phone opens to a desktop (`BleClient`, the re-attest flow in
`DeviceDetailActivity`) never show the short authentication string, so a
machine in the middle goes unnoticed. The phone computes the SAS from the
session it holds (`AttestTranscript.shortAuthString` over the initiator's
`sessionBinding()`, the same value the desktop derives from the same
transcript), shows it through the same confirmation the accepted sessions use
(`PairingConfirmationCallback.onPairingConfirmationRequired` with the SAS), and
trusts the session only once the user confirms. Rejecting aborts the
connection and stores nothing. Nothing on the wire changes.

## Slices, in order

1. Tests first (`BleClientPhoneInitiatedSasTest`, `ShortAuthStringTest`):
   - confirm: the callback gets the SAS the desktop derives and the desktop's
     key fingerprint; `connect` returns and the session is up;
   - reject: `connect` throws, the client is disconnected, and a
     `local.attestDevice` the desktop sent meanwhile never reaches the handler;
   - the desktop's `local.attestDevice` waits for the user's answer;
   - no confirmation callback: the session is refused (no unattended trust);
   - a fixed binding pins the SAS (`3181-4707-2325`, computed independently),
     the vector both tests share (`SasTestVectors`).
2. Fix: `BleClient` takes a `PairingConfirmationCallback`; after the Noise
   handshake it derives the SAS, asks the user, and only then reports the
   connection up; inbound requests wait on that answer; a rejection
   disconnects. `DeviceDetailActivity` passes a dialog that reuses the
   pairing dialog strings (`pairing_dialog_message_sas`), so the attestation
   result is recorded only after a confirmed session.
3. Docs: `docs/phone-initiated-pairing/architecture.md` describes the SAS step.

## Out of scope

- Any wire change, or the desktop's display of the SAS on sessions it accepts.
- The sessions the phone accepts (`GattServer`, `StreamPairingSession`): they
  already show the SAS.
