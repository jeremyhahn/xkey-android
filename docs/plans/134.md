# Plan: USB accessory detach and reattach (#134)

## Objective

Nothing handles `USB_ACCESSORY_DETACHED`. A pulled cable leaves the accessory
streams, the file descriptor and the session scope open. The server keeps its
connection slot, and the service keeps its server, so the next
`USB_ACCESSORY_ATTACHED` is ignored until the service restarts.

## Slices, in order

1. **Failing tests** (`test(usb): ...`), `UsbAccessoryServerTest`:
   - a detach of the open accessory closes its file descriptor, reports
     `Disconnected` and tells the owner (the `onDetached` callback);
   - a detach of a different accessory leaves the open one alone;
   - after a detach, a later attach opens the accessory again on the same
     server (reattach without a service restart);
   - a session that ends by itself (the host closed the stream) frees the
     connection slot, so a later attach opens the accessory again;
   - the detach watcher starts on connect and stops on disconnect.
2. **Fix** (`fix(usb): ...`):
   - `UsbAccessoryServer` takes an `AccessoryDetachWatcher` (production:
     `BroadcastAccessoryDetachWatcher`, a receiver registered for
     `ACTION_USB_ACCESSORY_DETACHED` while an accessory is open) and an
     `onDetached` callback;
   - on detach of the open accessory (or one the intent does not name) it
     disconnects: closes the streams and descriptor, cancels the session
     scope, stops the watcher and reports `Disconnected`;
   - a session that ends by itself releases the slot;
   - `XKeyGattService` passes `onDetached = ::onUsbAccessoryDetached`, so it
     drops its server and the next attach builds a new one.
3. **Comment fix**: `FrameBudget.GENERATION_RESERVE` says `Response` has
   no generation, but `Response` carries one (the handler echoes the
   request generation). The comment now matches `Response`.
4. **Review fixes**: a detach test whose session is still running (held in
   its key load) asserts the detach cancels it. The service publishes its
   server, under a lock, before `connect` starts watching for the detach,
   and a detach clears only the server it belongs to.
5. **Second review fix**: the server watches for the detach before
   `openAccessory` (the broadcast is not sticky) and stops watching on a
   refused open. Every close other than `disconnect()` — a detach, a session
   that ends with no broadcast, a refused open — calls `onClosed`, so the
   service drops the server and serves the next attach.
6. **Third review fix**: the service's USB server slot (publish before
   connect, drop on `onClosed`, clear on detach) moves into
   `UsbAccessoryServerSlot`, so a unit test can deliver a detach through the
   production `BroadcastAccessoryDetachWatcher` receiver into it and check
   that the next attach starts a new server. The watcher takes its receiver
   registration as a seam (the unit-test android.jar has no `IntentFilter`;
   Robolectric is not on the test classpath).
7. **Pre-push review fix**: each opened USB connection sets a fresh session
   id on the shared request handler, so a PER_SESSION biometric approval
   does not carry over a detach and reattach. The slot waits (up to 5 s) for
   the previous session's teardown before it opens the next server, so that
   teardown cannot clear the new session's peer identity.
8. **Docs**: after merging main, `docs/usb-transport/architecture.md` lists
   `AccessoryDetachWatcher` and `UsbAccessoryServerSlot`, describes the
   server's close on detach, and gains a Detach and reattach section with a
   sequence diagram.
9. **Second pre-push review fix**: `RequestHandler.signWithBiometric` no
   longer tries `signWithoutBiometric` first for a PER_SESSION session that
   `SessionAuthManager` has not approved, so a reattach inside the Keystore's
   auth window still prompts. The connected peer identity records the session
   that set it, and `StreamPairingSession`'s teardown clears it only through
   `clearConnectedDevicePublicKeyHex(owner)`, so a teardown that ends after
   the slot's 5 s wait leaves the replacement's identity in place.

## r8: connect failure unwinds the slot

The slot publishes its server before `connect()`, so a connect that throws
(for example `openAccessory` refusing with `SecurityException` after the
detach receiver registered) never reaches `onClosed`. `open()` now catches
the failure, removes the server from the slot, disconnects it (stopping the
detach watcher and closing any opened descriptor) and rethrows.
`UsbAccessoryServerSlotTest` covers an open that throws and a connect that
throws after the open; in both the slot is empty and the next attach works.

## r9: connection-scoped approval and probe migration

One `RequestHandler` serves BLE, TCP and USB, and a USB reattach sets a new
session id on it. A BLE or TCP sign whose prompt was still open recorded its
approval against the id read after the prompt, the new USB session's, so
that session's first protected sign skipped its prompt. `handleRequest` now
captures the session id when the request arrives and carries it in the
coroutine context (`ApprovalSession`); `sign`, `local.sign` and the FIDO2
assertion check and record approval against it.
`PerSessionApprovalReattachTest` holds a prompt open across a reattach and
checks the new USB session still prompts (committed failing first).

`XKeyGattServiceProbe` reads `usbServerSlot` and installs a server in it
without connecting; `usbIsUsedWhenBleIsIdle`, `bleWinsOverUsb` and
`detachingTheUsbAccessoryClearsItsTransport` use it.

## Out of scope

- No wire change, no SPEC change, nothing in go-xkms.
- A manifest receiver is not needed: the detach broadcast reaches the
  receiver registered at runtime while an accessory is open.
- The service's attach path is otherwise unchanged (the native-USB setting
  check, per-session vault).
