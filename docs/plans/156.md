# #156: an issuer containing a colon keeps its account name

## Objective

`OathRepository.importFromUri` reads the decoded URI path and `parseLabel`
splits it at the first `:`. `otpauthUri` (sync) percent-encodes a `:` inside
the issuer as `%3A`, but the decoded path no longer tells that `%3A` from the
label separator, so the issuer is cut at its own colon and the rest is
prepended to the account name.

Fix: split the label on the first literal `:` of the encoded path
(`Uri.encodedPath`), then percent-decode the issuer and the account apart.

## Slices, in order

1. This plan.
2. Test commit (fails on main): `OathLabelTest`, a JVM unit test of a new
   internal pure function `parseOathLabel` in `oath/OathLabel.kt`, covering
   an issuer with `%3A`, an account with `%3A`, both, no issuer, and an empty
   issuer (plus whitespace trimming and `%20`/`%40` decoding kept as today).
   The commit adds the function with the old split-after-decode behaviour, so
   the colon cases fail.
3. Fix commit: `parseOathLabel` splits the encoded label first and decodes
   each part (UTF-8, `+` kept literal as in a URI path);
   `importFromUri` passes `parsed.encodedPath` to it, and the private
   `parseLabel` goes.

## Out of scope

- `otpauthUri` encoding (already encodes `:` as `%3A`).
- The `issuer` query parameter, which still wins over the label prefix.
- Any other import behaviour.
