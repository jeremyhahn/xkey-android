# #156: an issuer containing a colon keeps its account name

## Objective

`OathRepository.importFromUri` reads the decoded URI path and `parseLabel`
splits it at the first `:`. `otpauthUri` (sync) percent-encodes a `:` inside
the issuer as `%3A`, but the decoded path no longer tells that `%3A` from the
label separator, so the issuer is cut at its own colon and the rest is
prepended to the account name.

Fix: split the label on the first literal `:` of the encoded path
(`Uri.encodedPath`), then percent-decode the issuer and the account apart.

## Slices, in order

1. This plan.
2. Test commit (fails on main): `OathLabelTest`, a JVM unit test of a new
   internal pure function `parseOathLabel` in `oath/OathLabel.kt`, covering
   an issuer with `%3A`, an account with `%3A`, both, no issuer, and an empty
   issuer (plus whitespace trimming and `%20`/`%40` decoding kept as today).
   The commit adds the function with the old split-after-decode behaviour, so
   the colon cases fail.
3. Fix commit: `parseOathLabel` splits the encoded label first and decodes
   each part (UTF-8, `+` kept literal as in a URI path);
   `importFromUri` passes `parsed.encodedPath` to it, and the private
   `parseLabel` goes.

## Out of scope

- `otpauthUri` encoding (already encodes `:` as `%3A`).
- The `issuer` query parameter, which still wins over the label prefix.
- Any other import behaviour.

## r2: one separator contract for import and manual entry

Review found that `OathActivity.buildOtpauthUri` passes `issuer:account` to
`Uri.Builder.appendPath`, which encodes the separator as `%3A`, so the
literal-only split stored `GitHub:alice@example.com` as the account. And
`URLDecoder` throws on a malformed escape (`50% off`, `%zz`) where main's
`Uri.getPath` decoded leniently.

Contract: a literal `:` separates issuer and account; a `:` inside either is
`%3A`. With no literal `:`, an encoded `%3A` separates them only when the
decoded prefix equals the `issuer` query parameter (as old manual-entry
URIs and third-party codes write it); otherwise the label is all account, so
sync's issuerless `host%3Auser` stays whole. The `issuer` parameter still
wins for the issuer.

4. Test commit: `OathManualEntryUriTest` (JVM round trip of a new pure
   `manualOtpauthUri` builder through `parseOathLabel`): GitHub /
   alice@example.com, an issuer containing `:`, an issuer-prefixed `%3A`
   label; `OathLabelTest` lenient-decode cases; `OathManualEntryFlowTest`
   asserts the persisted account and issuer (compiled only).
5. Fix commit: `manualOtpauthUri` encodes each part and joins them with a
   literal `:`; `buildOtpauthUri` calls it; `parseOathLabel` takes the
   `issuer` parameter for the `%3A` fallback and decodes leniently;
   `importFromUri` passes the parameter (one line in `OathRepository.kt`).

## r2: external import compatibility

Review: `otpauth://totp/GitHub%3Aalice?secret=...` with no `issuer`
parameter stored a null issuer and account `GitHub:alice`; main's importer
split it into `GitHub` / `alice`. Third-party codes rely on that.

Contract, two paths:
- Import (`parseOathLabel`, QR scan, URI paste, protocol import): a literal
  `:` separates first; else the `%3A` after a prefix equal to the `issuer`
  parameter; else the first `%3A`, as main did. The `issuer` parameter
  still wins for the issuer, so a differing parameter is kept as given and
  the label prefix is dropped from the account (main's behaviour).
- Structured (`parseStructuredOathLabel`, manual entry and sync, which hold
  issuer and account as separate fields and join them with a literal `:`):
  only a literal `:` separates, so an issuerless `a:b` stays whole.
  `importFromUri(uri, structuredLabel = true)` takes this path.

6. Test commit: `OathLabelTest` import cases (encoded and literal separator
   without a parameter, matching and differing parameter) fail; the
   structured cases and `OathManualEntryUriTest` move to
   `parseStructuredOathLabel` (added delegating, so they pass).
7. Fix commit: the import fallback splits on the first `%3A`;
   `parseStructuredOathLabel` splits on a literal `:` only; `OathActivity`
   manual entry and `SyncEngine.mergeOath` pass `structuredLabel = true`.
