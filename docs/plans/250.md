# Plan: #250 TpmMakeCredentialTest wrong-key flake

## Objective

`TpmMakeCredentialTest > a different endorsement key cannot recover the seed`
failed on main because RSA-OAEP decryption under a wrong private key can fail
with exception types other than `IllegalStateException` or
`BadPaddingException`, depending on the random key pair. The test asserted the
type in a catch clause, so the outcome depended on the generated keys.

Fix the class: the test helper `softwareActivateCredential` is the one choke
point. Every failure of its OAEP unwrap, integrity check or credential decode
surfaces as `IllegalStateException` (cause kept). The tests assert only that.

## Slices

1. Plan (this file).
2. Test-only fix in `TpmMakeCredentialTest.kt`:
   - `softwareActivateCredential` wraps every unwrap/integrity/decode failure
     in `IllegalStateException`;
   - the wrong-key test asserts `IllegalStateException` via `assertThrows`;
   - a new test runs the wrong-key case over 50 generated EK pairs.
   Tests: `:app:testDebugUnitTest --tests '*TpmMakeCredentialTest*'` five runs
   with `--rerun-tasks`, then the full `:app:testDebugUnitTest` once.

## Out of scope

- Production code: `TpmMakeCredential` only encrypts (the desktop TPM
  unwraps), so no production code shares the unwrap.
