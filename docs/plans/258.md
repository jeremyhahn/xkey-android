# Plan: SPEC row media-signing (#258)

## Objective

Ship SPEC row `media-signing`: a foreground service watches MediaStore,
hashes new photos and videos, signs them and embeds the signature in EXIF
or XMP, with an auto-sign toggle and key choice. Videos and PNG/WebP photos
embed the signature in XMP, not in a sidecar file (#200).

## Slices, in order

1. Fold PR #212 (`row/200-media-xmp-embed`, head f1081069) with
   `git merge --no-ff`. One conflict, in `ui/FileOperationActivity.kt`
   (the field block after `pickSidecarLauncher`). Resolution: keep main's
   staging fields (`staging`, `pendingEncryptedSave`, `pendingDecryptedSave`,
   from #205) and add #212's `createSignedCopyLauncher`, `PendingSignedCopy`
   and `pendingSignedCopy`. Drop #212's `pendingEncryptedUri` and
   `pendingDecryptedUri`; main's PendingStagedSave replaces them.
   Tests that come with it: XmpContainersTest, XmpMetadataHelperSidecarBranchTest,
   AutoSignHashTest, MediaHasherCanonicalTest, and the instrumented
   XmpMetadataHelperInstrumentedTest.
   Done: merged with that resolution.
2. Run the media and ui unit tests (`testDebugUnitTest`) on the merged tip.
   The Makefile has no per-feature integration target; `make
   integration-test` (connectedDebugAndroidTest, incl.
   XmpMetadataHelperInstrumentedTest) needs a device, so CI runs it.
3. Review fixes. `isAddedVp8x` gets a block body. One embed choke point,
   `writeEmbeddedSignature`: every unsigned MP4/MOV, PNG and WebP is embedded
   streaming at any size (`XmpContainers.embedFile`, same bytes as `embed`);
   `maxEmbedBytes` bounds only rewriting a carried packet, so no camera video
   falls back to a sidecar. Co-signing stages its working copy with the
   media's own suffix (`XmpMetadataHelper.stagingSuffix`), so PNG, WebP and
   MP4/MOV co-signatures append in XMP. Tests: XmpEmbedFileTest (streamed ==
   in-memory per format, round trip, above-bound embed, co-sign append), and
   the above-bound cases in AutoSignHashTest and XmpMetadataHelperSidecarBranchTest.
4. docs/SPEC.md already lists the row as shipped; the PR body ticks #200/#212
5. Round-3 review fixes. Verification and URI signing hash streaming: one
   canonical plan (`MediaHasher.canonicalPlan` over a `ByteSource`) serves
   bytes in memory and streams, so a video larger than the heap verifies
   (MediaHasherStreamingTest). The co-sign picker offers every
   embedded-signature type (`XmpMetadataHelper.EMBEDDED_MIME_TYPES`,
   CoSignMediaPickerTest). FileOperationActivity sends every save picker's
   result through `onSavePicked` (a cancel clears the pending output and the
   busy state) and keeps the sidecar JSON and the pending signed copy in its
   saved state (FileOperationSavePickerTest).
6. Key-use record. `RequestHandler.logKeyUse` is the one place a completed
   key use is recorded: it writes the usage and the audit entry together
   under `NonCancellable`, so a request cancelled after its key operation
   (desktop disconnect or unpair) still leaves both. Sign, decrypt, AES
   (Keystore and software), HMAC (both branches), ECDH and co-sign record
   through it; the OATH code entry is written under `NonCancellable` with
   its lookup. HmacEcdhAuditTest cancels each request at both post-operation
   suspensions; KeyUseRecordChokePointTest fails on any bypass.
7. Trust-store file outcome. Every trust-store file removal or restore
   reports a `FileOutcome` (removed / still present / unknown) through
   `removeFile` or `restoreFile`; a failed restore cleans up through
   `removeFile`, whose outcome is checked. Delete and clear record a
   deletion (and the screens drop the row) only on a proven removal, so a
   restore whose close throws after the whole DER and whose cleanup fails
   leaves the CA trusted and its row kept (TrustStoreDeletionTest);
   TrustStoreFileOutcomeChokePointTest fails on a raw Boolean read.
8. Bounded media plans. Every media format parser (JPEG, PNG, WebP,
   MP4/MOV) plans the canonical hash through `MediaPlan.Builder`, which
   coalesces adjacent ranges and refuses past `MediaPlan.MAX_PIECES` pieces
   with `MediaTooFragmentedException`, an IOException the sign and verify
   screens report. A JPEG of millions of tiny markers hashes as one piece;
   one whose markers are split by fill bytes is refused (MediaPlanBoundTest,
   which also fails on a piece or plan made outside the builder).
9. Restored save busy state. A save restored after recreation keeps
   Process disabled until its picker is cancelled or its write ends
   (FileOperationSavePickerTest holds the restored writer open and taps
   Process).
10. Safe media publication. `MediaPublisher` is the one path that writes
    where the user keeps media (sign, co-sign, XMP, EXIF and sidecar
    writes): a file it can reach by path is replaced atomically (temp file
    beside it, synced, renamed over it); any other provider gets a separate
    copy the user creates, and the original is only read. The bytes being
    published stay in `media-recovery` until the write and close both
    succeeded; a failure names them. CoSignPublishTest fails the copy's
    stream and finds the original whole and the co-signed bytes kept;
    MediaPublisherTest fails on any writing open or in-place EXIF rewrite
    outside the publisher.
11. Running save state. A save the user has placed is no longer a pending
    picker: it is saved as a running save, re-attached by a recreated
    screen (or run again after process death), and clears busy when it
    ends (FileOperationSavePickerTest rotates during the write).

## Out of scope

- New signing formats beyond EXIF (JPEG) and XMP (video, PNG, WebP).
- Desktop-side verification changes (go-xkms).
