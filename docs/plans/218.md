# #218: the co-sign QR exchange scans both codes and appends the co-signature

## Objective

The QR co-sign flow in `CoSignActivity` works end to end. Today the witness
types the content hash by hand, the owner never scans the witness's response
QR, and no co-signature is ever written to the media. After this row:

1. The owner picks a signed JPEG with `OpenDocument` (persistable read and
   write) and shows the request QR `{"v":1,"hash","alg","from"}`. Media with no
   signature data is refused with a message.
2. The witness scans the request QR, sees the content hash and the owner's
   fingerprint, approves, signs the hash and shows the response QR
   `{"v":1,"sig","fp","name","alg"}`.
3. The owner scans the response QR; it becomes a `SignatureEntry` with role
   `ATTESTOR` and is appended to the media. A response from a key that has
   already signed is refused and the media is unchanged.

## Slices, in order

1. This plan.
2. Failing JVM tests:
   - `media/CoSignPayloadTest`: request and response round-trip; unknown
     version, each missing field, a hash that is not lowercase hex of the
     algorithm's digest length, an unsupported hash algorithm, a non-base64
     signature and a non-JSON payload each give a distinct typed error; a
     response becomes an `ATTESTOR` entry with the response's fp, name, alg and
     sig and an ISO-8601 timestamp from an injected `Clock`; a duplicate
     signer is refused and the data is unchanged.
   - `ui/QrPayloadFilterTest`: `otpauth://` accepted by default (and for an
     unknown or missing kind); a co-sign JSON payload only when the intent asks
     for it; never both.
3. Code:
   - `media/CoSignPayload.kt`: pure parser (`CoSignRequest`, `CoSignResponse`,
     sealed `CoSignPayloadError`), `toJsonString`, `toAttestorEntry(clock)` and
     `appendAttestor(data, entry)` with the duplicate-signer refusal. No
     Android imports (`java.util.Base64`, `java.time.Clock`).
   - `ui/QrPayloadFilter` + `QrScannerActivity.EXTRA_PAYLOAD_KIND`: the
     scanner accepts the kind the intent asks for; the default stays otpauth,
     so `OathActivity` is unchanged.
   - `CoSignActivity`: OpenDocument picker; witness "Scan request" flow with an
     approval dialog; owner "Scan witness response" flow that appends through
     a cacheDir temp copy (`XmpMetadataHelper.appendSignature`), writes back
     with `openOutputStream(uri, "rwt")` and deletes the temp file in `finally`.
   - New strings in `res/values/strings_cosign.xml`.

## Out of scope

- BLE mode (`cosign.request` over a live session, held #177).
- Verifying the witness signature on the owner device: the response carries
  only the key fingerprint, not the public key; verification stays with the
  existing verify flow and contacts.
- Non-JPEG media: `readSignatureFromUri` reads EXIF only, so the picker asks
  for `image/jpeg`.
