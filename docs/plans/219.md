# Plan: record key attestations in the audit log (#219)

## Objective

SPEC feature `audit-log` records security events in Room, and
`hardware-backed-keys` lists key attestation, yet `local.attestKey`
(`RequestHandler.handleLocalAttestKey`) writes no audit entry:
`AuditLogger.logKeyAttested` has no caller in `app/src/main`. Every key
attestation the phone answers, or fails to answer, must leave one
`KEY_ATTESTED` entry.

## Slices

1. **Failing tests** (`protocol/LocalAttestKeyAuditTest`), driving the real
   `RequestHandler` with `AuditLogger` mocked (`mockkObject`):
   - a successful `local.attestKey` records exactly one `KEY_ATTESTED`
     entry with success, the key id, the key's label and type and the
     parsed security level; the response JSON keeps its fields;
   - a keystore that returns no chain records one failed entry and the
     reply is still `ATTESTATION_FAILED`;
   - missing params and a stale device attestation are refused before any
     attestation and record no `KEY_ATTESTED` entry.
2. **Fix**: `handleLocalAttestKey` calls `AuditLogger.logKeyAttested` once
   on success (label and type from `keyDao`, key id fallback; security
   level; duration) and once with `success = false` before throwing
   `ATTESTATION_FAILED`.
3. **Docs**: `docs/audit-log/architecture.md` lists key attestation among
   the recorded events.

## Out of scope

- `logKeyAttested` takes no caller device id or name, and `AuditLogger`
  is not edited in this row; recording the caller device for attestation
  entries is a follow-up.
- PIV handlers, the Room schema and `AuditLogActivity`.
