# Plan #177: cosign.request signs only after the owner approves

## Objective

`RequestHandler.handleCosignRequest` signed whatever hex `hash` a peer sent,
at once, on every transport. After this change it:

1. refuses a session with no confirmed peer (`OPERATION_DENIED`);
2. checks `hashAlgorithm` is known and `hash` decodes to exactly its digest
   length; otherwise `INVALID_PARAMS`;
3. signs only with a `signing` key: a named key of any other type (FIDO2
   included) is `OPERATION_DENIED`, and the fallback never picks a FIDO2 key;
4. asks the owner on the phone, naming the first 8 hex characters of the
   hash; no launcher, a cancel, a failure or no answer is `BIOMETRIC_FAILED`
   and nothing is signed;
5. keeps the success result shape (`signature`, `keyFingerprint`,
   `algorithm`, `signerName`).

## Rounds r1-r5 (done)

- Failing tests then the fix in `handleCosignRequest`; the instrumented
  `RequestHandlerFido2AndCosignTest` cosign cases follow the new behaviour.
- r2: a request with a `CallerSession` is decided by that session's peer,
  confirmed only when the paired-device store knows it; share and import use
  the same check. Requests with no caller session keep the global field.
- r3-r5: a private co-sign prompt queue with its own cancel action. Deferred
  to #178: it did not serialize with the launcher's prompts, and a cancel
  sent before the activity came up was lost.

## r6: the co-sign prompt is an entry in the shared prompt queue

#207 landed `PromptOwnership`, the one process-wide prompt queue. Review P1s
on r5: the private `promptLock` serialized only co-sign prompts (F1); the
cancel broadcast was lost before `onCreate`, and the lock released on a timed
out wait (F2).

14. Merge main (with #207), never rebase. `TransparentBiometricActivity`,
    `BiometricNotificationHelper` and `BiometricActivityLauncher` take main's
    side; the co-sign's own cancel action and notification intent are gone.
15. Failing tests: in `CosignRequestHandlerTest` a co-sign and a FIDO2 prompt
    take turns in both orders (the overlap test is no longer ignored); a
    co-sign withdrawn before its activity comes up never shows and the next
    one is answered. `PromptEntryPointsTest` adds a bypass guard: every
    prompt activity intent is built inside a `PendingAuthentications.await`
    turn, which enqueues before it launches.
16. Fix: `CosignApprovalPrompts` is a client of
    `BiometricActivityLauncher.requestAuthentication`, which is the one
    choke point. It enqueues an `approval-<id>` key, launches only when the
    key is ACTIVE, and maps the result, the deadlines and a withdrawal onto
    that key. The activity prompts only for an ACTIVE key, so a withdrawal
    recorded before `onCreate` finishes it. The queue moves on only when
    the key settles. The 60 s owner timeout starts at launch; the
    lock-screen notification uses the same key (`OwnNotifications`).
17. The merge kept the r2 paired-device check in `requireConfirmedPeer`.
    The SetKeyPolicy tests now pair their caller peer.

## Out of scope

Session-cached approval; the initiator side (`CoSignActivity`) and
`cosign.response`; hash algorithms other than SHA-256, SHA-384 and SHA-512.
